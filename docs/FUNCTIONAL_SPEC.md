# 연이음 기능명세서: 필수·부가·확장

버전 0.5 / 갱신 2026-11-12, Asia/Seoul. [개발 브리프](DEVELOPMENT_BRIEF.md), [권한 명세](ACCESS_CONTROL.md), [조직 구조](ORGANIZATION_MODEL.md), [테스트·시연 기준](ACCEPTANCE.md)에 연결한다.

## 1. 분류와 상태

사용자가 요청한 필수·부가·확장 분류의 제안 초안(P)이다. 기능별 우선순위·상세 동작은 검토 후 확정한다. 기존에 사용자에게 확인된 사실(C)을 축소하거나 미정인 운영 절차를 새로 확정하지 않는다. 현재 M-01~03의 가상 계정·소속·역할 기능과 역할 감사 일부를 로컬 프로토타입으로 구현했다. 실제 운영 인증·초대 메일·개인정보 정책과 자료·회계·인수인계·AWS는 미완료다. 구현·검증 범위는 [프로토타입 가이드](PROTOTYPE.md)를 따른다. 최신 핵심 흐름과 도메인 결정은 [도메인 모델](DOMAIN_MODEL.md)의 사용자 Q1~54·DM-C01/02를 반영하며, M/A/X 세부 분류와 미결정 정책을 구분한다.

| 분류 | 의미 | 적용 시점 제안 |
|---|---|---|
| 필수 M | 자료·예산·권한·인수인계의 핵심 업무를 완료하고 기록을 보호하는 데 필요한 기능 | 첫 버전 |
| 부가 A | 핵심 업무를 더 편리하게 수행하도록 돕는 기능. 없어도 핵심 흐름은 완료 가능 | 필수 완료 후, 시간·사용자 요구에 따라 |
| 확장 X | 새로운 업무 영역·연동·고급 자동화를 추가하는 기능 | 시범 사용 후 우선순위 재평가 |

기능 ID는 이 문서의 세부 항목이며 기존 F-01~10을 대체하지 않는다. M/A/X는 우선순위, C/R/P/O는 결정 상태다. 보안·보존·백업·복구 등 공통 요건은 부가 기능으로 미루지 않는다.

확정된 전제:

- 연암공과대학교의 총학생회·학과협의회·신문방송국·연합동아리·모니터링단 5개를 기본 소속으로 하며 선생님이 신설 단체를 관리한다(S18).
- 첫 버전은 담당자 중심으로 사용한다. 담당 선생님은 서비스 관리자이며 각 단체 최고 책임자 권한을 부여한다. 모니터링단·신설 단체의 구체 직책명은 후속 확인한다.
- 최고 책임자는 자기 단체의 하위 역할을 부여하고 학회장은 부학회장·반대표를 직접 지정한다.
- 의장(학과협의회장)은 자기 학과 학회장을 겸한다. 학회장들이 학회장 중 투표로 의장을 선출하며, 하나의 계정이 두 담당 범위를 함께 갖고 공식 임기는 같다(DM-C05). 학회장 자격 종료 시 의장도 종료한다(DM-C02). 반대표의 담당 범위는 학과→학년→반이다(DM-C01).
- 예산은 각 단체 최고 책임자가 보유·관리한다. 일반 지출 본인 확인은 허용하며 담당 선생님은 미처리 항목을 처리한 뒤 전체 정산을 확정한다. 초과분 예외는 해당 단체 최고 책임자가 최종 확인하되 본인 집행 건은 선생님이 확인한다(DM-C03). 처리 결과·민감 자료 열람의 세부 범위는 미정이다.

## 6. 첫 버전 완료 범위와 다음 결정

첫 버전 완료 제안은 M-01~12, 위 공통 요건, 기존 [8개 완료 조건](ACCEPTANCE.md)을 모두 만족하는 기준이다. 로컬 기능 완성과 실제 AWS 통합·과제 완성은 구분한다. A/X가 미구현이어도 이 범위를 충족하면 첫 버전 완료를 판정할 수 있다. 실제 학교 시범 운영에는 별도 운영 게이트가 추가로 필요하다.

사용자와 다음을 검토해 분류를 확정한다.

1. 공지·대시보드·알림 중 첫 버전의 필수로 올릴 항목이 있는지.
2. M-09의 초과분 처리 결과·후속 절차, 환불·정정 처리자와 반영 시점. 초과분 확인자는 DM-C03, 실제 집행 기준 잔액·검토 상태별 표시는 DM-C04로 확정됐다. 실제 발생 지출 기록·일반 본인 확인·선생님 전체 정산 확정은 이미 확정됐다.
3. 각 자료·회계 업무 권한 묶음과 민감 자료 분류별 열람 범위.
4. 기간 경계·역할 회수 상세, 파일 형식·검사·보존, 실제 소속 목록·정원. 50 MiB·학과/학년/반·의장 선출 주체·공유 임기·종료 의존 관계는 확정됐다.

위 결정은 개발 브리프 O-01~04/08~10/12~13과 함께 갱신한다. 분류 초안을 작성했다는 이유로 사용자 승인이 필요한 미정 운영 정책을 확정하지 않는다.

## 관리자 조직·담당자 보완 (2026-11-13, S18)

M-01: 등록 소속은 운영 중인 단체만 표시하며 전화번호 자동 하이픈을 제공한다. 선생님만 담당자를 제거할 수 있고 ‘담당자를 제거하시겠습니까?’ 창에서 ‘제거하겠습니다’를 정확히 입력해야 한다. 계정 제거와 역할 회수는 별개이며 계정 제거는 해당 계정의 모든 역할과 세션을 종료한다. 이력은 보존한다.

M-02/03: 선생님의 단체 추가·삭제를 제공한다. 단체 삭제는 해당 ‘삭제하겠습니다’ 확인 문구 입력 후 운영 제외·소속 역할 종료로 처리한다(P). 학과·학년·반 데이터는 권한 범위를 위해 유지하며 등록 소속에서만 숨긴다. 단체 단위로 등록한 소속은 최초 세부 역할을 지정할 때 구체화한다. 역할 부여 결과와 입력 오류는 폼 안에서 확인할 수 있다. 신규 단체 추가가 회계 권한·전체 자료 열람을 자동 부여하지 않는다.

단체명 중복 검사는 운영 상태를 구분한다. 운영 중인 동명 단체는 거절하고 삭제된 동명 단체는 기존 ID·하위 소속을 복원한다. 복원 결과를 화면에 표시하고 이전 역할·제거된 계정은 자동 복구하지 않는다.

## S19 등록·초대 보완 (2026-11-13)

M-01: 학생 신규 등록의 학번은 숫자 8자리, 비밀번호는 8자 이상 숫자·특수문자 포함이다. 소속은 복수 선택하며 각 소속의 등록 권한을 서버에서 검사한다. 동일 학번+이메일의 삭제 계정은 선생님이 복구할 수 있고 이전 역할은 자동 복구하지 않는다. 복구 계정도 새 초대 인증이 필요하다.

초대·인증의 현재 범위는 사용자 선택에 따라 로컬 수신함이다. 24시간·1회 사용 링크, 만료·재발급·삭제 무효화를 제공한다(P). 신규·복구 계정은 인증 전 로그인과 업무 역할을 사용할 수 없다. 이메일 형식 검사·로컬 초대 확인과 실제 이메일 수신·실존 확인은 구분한다. 실제 전송은 서비스·발신 주소·공개 HTTPS 주소 확인 후 연결한다. [구현 계약](design/INVITATIONS.md).

## S20 역할 종류·범위 선택 보완

M-02/03: 선생님은 모든 유효 범위의 역할을 부여하고 단체별 역할 종류를 추가·삭제한다. 단체 → 담당 범위 → 역할 → 담당자 → 임기 순서로 선택한다. 부서 등록·동아리 등록과 학과/학년/반의 하위 조직 등록을 제공한다.

총학생회·신문방송국의 부장/차장은 각 부서에, 동아리 회장/부회장/총무는 각 동아리에 부여한다. 삭제는 해당 단체의 종류와 현재·예약 부여를 회수하며 이력을 유지한다. 재추가는 정의 복원만 한다. 새 직책 이름에 재위임·회계 권한이 자동 부여되지 않는다. [세부 계약](design/ROLE_CATALOG.md).

S21: M-02/03의 ‘역할과 임기’는 회수되지 않은 역할만 표시한다. 유효·시작 대기·비활성 역할은 기존 상태 기준으로 구분한다. 회수 사실은 감사 기록에 보존한다. 자동 입력 임기는 해당 연도 01-01~12-31이며 마지막 날짜까지 포함한다. 의장의 연결 임기는 그대로 공유한다.

## S22 학회장 위임과 자료실 공유 대상 준비

M-01~03: 학회장이 자기 학과 안에 학년·반을 만들고 반대표 계정을 등록·초대하며 해당 범위 역할을 부여한다. 부학회장·반대표에게 재위임을 자동 부여하지 않는다. 선생님은 기존 전체 관리자 권한을 유지한다.

M-04~06 후속 기준: 공유 대상은 ‘학과협의회 간부진(학회장·부학회장)’과 ‘각 학과 담당자(학회장·부학회장·반대표)’를 구분한다. 현재는 그룹 표시와 서버 참여 정책만 구현했으며 실제 파일·문서 권한은 자료실 구현 시 연결한다. 공유 그룹 참여 때문에 다른 학과 계정·연락처 관리 범위를 넓히지 않는다.

의장 지정은 학회장 카드에서 선출 확인 후 기존 동일 인물·기간을 연결하고 의장만 해제할 수 있다. [세부 모델과 후속 검증](design/ACADEMIC_SCOPES.md).
