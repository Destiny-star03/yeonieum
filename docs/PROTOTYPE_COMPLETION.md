# 프로토타입 완료 기준과 현재 상태

기준일: 2026-11-13. 최신 사용자 결정 S18~S22와 [전체 수용 기준](ACCEPTANCE.md)을 따른다. 현재 범위는 로컬 가상 데이터의 조직·권한 프로토타입이다. 아래 단계별 완료 판단은 범위를 구분하기 위한 P 기준이며 실제 학교 도입·운영 인증의 승인을 의미하지 않는다.

## 1. 현재 조직·권한 프로토타입

| 완료 조건 | 확인할 결과 | 현재 근거 |
|---|---|---|
| 계정 등록·초대·복구 | 숫자 8자리 학번, 비밀번호 8자 이상 숫자/특수문자, 복수 소속, 로컬 초대 인증 전 로그인 차단, 삭제 계정의 동일 학번+이메일 복구 | API/브라우저 검증. 실제 메일 발송·학적 검증은 제외 |
| 조직·역할 관리 | 선생님이 단체·하위 조직·역할 종류를 관리하고 범위에 맞는 역할을 부여. 삭제·복원과 기존 기록 유지 | T-20~32, 기존 데이터 마이그레이션·재시작 보존 |
| 학과 위임 | 학회장이 자기 학과 학년/반 생성→반대표 계정 등록·초대→역할 부여. 타 학과·하위 담당자 재위임 차단 | T-18/34, 모바일 사용자 흐름 |
| 공유 대상 분리 | 학회장/부학회장은 협의회 간부진+자기 학과, 반대표는 자기 학과. 공유 대상이 계정/연락처 관리 권한을 확대하지 않음 | T-35와 그룹 참여 서버 정책. 실제 자료실은 미구현 |
| 의장·임기·회수 | 학회장 카드에서 의장 지정/해제, 선출 확인·같은 인물/공식 임기 유지. 기본 임기 01-01~12-31(한국 시간 당일 포함), 회수 즉시 권한 종료·목록 숨김·감사 보존 | T-19/33/36, 시각 경계·현재 세션 재검사 |
| 안전한 저장과 오류 처리 | 무권한 API 직접 호출 거절, 중복/실패 안내, 트랜잭션과 감사 일관성, 복구 시 옛 세션·역할·초대 무효 | API 실패·상태 전이 테스트와 읽기 전용 권한 검토 |
| 재현·품질·화면 | 실행 가이드·의존성 잠금·가상 DB, 데스크톱/모바일 주요 흐름, 공통 검사·Ruff·Prettier·타입·빌드·API·브라우저 테스트 통과 | 로컬 API 75개, 브라우저 11개. 원격 CI는 해당 PR의 실제 결과로 별도 확인 |
| 사용자 최종 시연 확인 | 선생님/학회장/부학회장/반대표로 주요 흐름을 직접 보고, 진행을 막는 결함과 미결정 범위를 기록 | 자동 검증과 구분하며 사용자 확인은 별도 |

현재는 기능·자동 검증을 충족한 로컬 시연 단계다. 사용자 시연 확인과 관련 PR의 원격 CI 결과를 함께 확인하면 조직·권한 프로토타입의 완료 판단 근거가 된다. 테스트 수만으로 전체 포털·운영 준비 완료를 판정하지 않는다.

### 권장 최종 시연

1. 선생님이 단체/하위 조직/역할 종류를 관리하고 담당자를 등록한다.
2. 로컬 초대 인증 후 해당 학번으로 로그인한다. 미인증·중복·잘못된 입력도 확인한다.
3. 학회장이 자기 학과의 학년/반과 반대표를 등록·초대·지정하고, 다른 학과 요청은 거절되는지 본다.
4. 학회장·부학회장·반대표의 두 공유 대상 그룹과 연락처 관리 범위 차이를 본다.
5. 선생님이 의장을 지정·해제하고, 학회장 종료에 따라 의장도 끝나는지 확인한다.
6. 역할/계정/단체를 제거·복구하고 옛 권한은 되살아나지 않으며 이력·데이터는 유지되는지 본다.

## 2. 전체 첫 버전 포털의 완료 조건

원래 [첫 버전 8개 완료 조건](ACCEPTANCE.md#3-첫-버전-완료-조건-8가지)은 아래 전체 흐름이 동작해야 한다. 현재 조직·권한 검증만으로 통과한 것으로 표시하지 않는다.

| 영역 | 전체 첫 버전에 필요한 동작 | 현재 상태 |
|---|---|---|
| 인증·조직·권한 | 조직 격리, 담당 범위·임기·위임·회수·겸임 | 로컬 프로토타입 검증. 운영 인증 후속 |
| 자료실 | 50 MiB 제한, 업로드·분류·검색·비공개 다운로드와 공유 대상별 서버/파일 URL 접근 통제 | 미구현 |
| 버전·과거 기록 | 이전 버전·증빙 연결 보존, 휴지통/복원, 계정 교체 후 기록 유지 | 문서/파일 기능 미구현 |
| 예산·지출 | 연간/행사 배정, 실제 지출·증빙·잔액·초과액을 일관되게 집계 | 미구현 |
| 검토·정산 | 개별 확인/반려와 선생님의 전체 확정 분리, 미처리 차단, 수정/초과 예외 이력 | 미구현 |
| 인수인계 | 연도별·중도 교체, 필수 체크리스트·인수 확인과 별도 역할 승인 | 미구현 |
| AWS·관측·복구 | 실제 클라우드 인증/저장/처리 연결, 오류 관측·재처리, DB+파일 백업 복원 증거 | 미구현/미검증 |
| 재현·전체 시연 | 새 환경 실행·배포 절차, 구성도, 정상/권한 거부/교체/복구 시연 | 로컬 실행 가이드만 있음. 전체 시연 후속 |

다음 구현 순서는 자료실의 업로드·검색·버전·권한별 공유/다운로드, 예산·정산, 인수인계, AWS 통합·복구 검증이다. AI 안내는 핵심 흐름 이후 확장으로 두며 도입하지 않은 AI를 전체 첫 버전의 필수 완료로 추가하지 않는다.

## 3. 실제 학교 사용 전에 추가로 필요한 조건

- 학교 도입 범위와 개인정보·민감 증빙·자료 보존/삭제·운영 책임자 합의.
- 학교 SSO/API 또는 승인 명부를 통한 실제 학생/교직원 확인, 최초 관리자 지정·복구 절차.
- 검증된 발신 주소·메일 서비스와 공개 HTTPS 초대 주소, 발송/반송/재발급 처리.
- AWS 계정·권한·비용·리전·운영 배포·모니터링·백업 복구 정책과 훈련.
- 실제 사용자 시범, 미해결 결함·보안/회계 무결성·복구 검증과 운영 매뉴얼.

현재 로컬 HTTP·가상 계정·로컬 초대 수신함은 이 운영 기준을 충족한 인증이나 실제 이메일 실존 확인이 아니다.
