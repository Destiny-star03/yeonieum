# 연이음 테스트·시연 기준

버전 0.10 / 2026-11-12, Asia/Seoul. [개발 브리프](DEVELOPMENT_BRIEF.md)의 요구 ID를 참조한다. 사용자 Q1~54·DM-C01/02의 확정 규칙과 보완 테스트 제안(P)을 구분한다. 아래는 아직 실행한 업무 테스트 결과가 아니다. 관계·근거는 [도메인 모델](DOMAIN_MODEL.md)을 따른다. [기능명세서](FUNCTIONAL_SPEC.md)의 필수 M-01~12는 기존 T-01~19와 연결된다. 부가 A·확장 X의 완료 기준은 해당 기능을 도입할 때 추가 검증하며, 미구현 선택 기능을 필수 테스트 통과로 표시하지 않는다.

## 1. 테스트 데이터와 실행 원칙

조직 구조의 근거는 [조직 구조·운영 주체](ORGANIZATION_MODEL.md)다. 시드 후보는 총학생회·학과협의회·신문방송국·연합동아리 4개 단체이며, 최고 책임자 직책은 각각 학생회장·의장·국장·연합동아리장이다. 아래 A/B는 초기 시연용 2개 단체다. 직책 시드는 총학생회·신문방송국의 부장·차장, 학과협의회의 학회장·부학회장·반대표, 연합동아리의 일반동아리장·동아리원을 구분한다. 사용 대상은 운영 담당자 중심이며, 구체적인 참여 하위 직책·인원과 자료·회계 기능은 O-02/O-13 결정 후 확정한다. 선생님이 4개 최고 책임자 역할을 부여하고 각 최고 책임자가 자기 단체 하위 역할을 부여하며, 학회장이 부학회장·반대표를 지정하는 체계는 확정사항이다. 의장 계정은 학회장들의 투표로 선출되어 자기 학과 학회장 역할도 겸하며 공식 임기가 동일한 시드로 구성한다(DM-C05).

학생성공센터 담당 선생님은 서비스 관리자 계정으로 포함하고 4개 최고 책임자 역할 부여를 검증한다. 기술 플랫폼 운영권은 별도다. 전체 현황·감사 조회와 전체 정산 확정을 검증하되 일반 자료·민감 증빙의 열람은 분리한다. 일반 지출 본인 확인은 허용하며, 초과분은 해당 단체 최고 책임자, 그 책임자 본인 집행 건은 선생님이 확인한다(DM-C03). 처리 결과·후속 절차는 O-04에서 구체화한다.

- 조직 A: 학과협의회, 조직 B: 총학생회. 운영기: 2026·2027. 학년도·임기 시작/끝은 명시적으로 설정한다.
- 계정: A의 기존 임원, A의 회계 작성자, A의 별도 승인자, A의 새 임원, A의 구성원, B의 임원, 플랫폼 운영자, 미승인 사용자. 일반 본인 확인 허용과 무권한 확인 거부를 검증할 회계 입력+확인 겸임 계정도 사용한다.
- 한 사용자의 A/B 복수 소속, 임기 중간 교체, 만료 직전/직후, 회수된 소속, 다음 학년도 대기 소속을 포함한다.
- 학과→학년→반을 기준으로 같은 반 이름의 다른 학년·학과와 서로 다른 부서·동아리 범위에 대한 허용/거부 사례를 준비한다. 실제 목록·정원은 O-13에서 결정한다. 이름이 같은 총학생회 부장과 신문방송국 부장의 권한이 섞이지 않는지 검증한다. 직책의 상하 연결만으로 권한·결재 단계가 자동 부여되지 않는 제안을 확인한다.
- 파일은 가상 회의록·행사 결과보고서·가상 영수증을 쓴다. 실제 개인정보·은행정보·내부 자료는 넣지 않는다.
- 회계 예시: 연간 예산 1,000,000원, 행사 배정 300,000원, 지출 100,000원. 이 한 건만 실제 발생했고 다른 미처리·정정이 없으면 사용 후 단순 잔액은 연간 900,000원·행사 200,000원이다. 검토 대기·확인 완료·반려 모두 실제 집행액에 포함한다. 환불·정정의 실제 반영 시점은 O-04에서 결정한다. 배정 자체를 지출에 더하지 않는다.
- 핵심 규칙은 단위 테스트, 관계·트랜잭션·권한은 PostgreSQL 기반 API 통합 테스트, 전체 흐름은 브라우저 E2E로 검증한다. 금액·인가·상태 전이의 핵심 실패 사례를 우선한다.
- 테스트 시간은 제어 가능한 시계를 사용하고 실제로 1년을 기다리지 않는다. 실제 AWS 구성은 테스트 계정에서 별도 확인한다. 모의 S3·토큰 통과를 AWS 검증으로 대체하지 않는다.

## 3. 첫 버전 완료 조건 8가지

원문에 세부 항목이 없으므로 아래 8개를 구현 판단 기준으로 제안한다. 기능명세서의 필수 기능·공통 요건과 함께 적용하며, A/X는 도입 범위가 확정된 경우에만 해당 추가 기준을 적용한다. 모두 통과해야 과제용 첫 버전 완료를 제안할 수 있다. 실운영에는 5절 운영 게이트가 추가로 필요하다.

| 번호 | 완료 조건 | 필요한 증거 |
|---|---|---|
| 1 | 로그인과 조직·역할·임기 인가, 관리자→최고 책임자→하위 역할 부여가 서버에서 동작 | T-01~03 및 T-17~19 결과, 다른 조직의 직접 요청 거부 |

## 4. 발표 시연 순서

6~10분 내 핵심 흐름을 보여주는 초안이며 발표 시간은 수업 안내에 맞춘다. 미리 준비한 가상 데이터를 쓰고 실습 환경에 대비한 녹화본을 함께 준비한다.

| ID | 시연 | 보여줄 결과 / AWS 근거 |
|---|---|---|
| D-01 | 2026 학과협의회 기존 임원 로그인 | Cognito 로그인과 자기 조직·학년도 표시. 임원별 역할 차이 설명 |
| D-02 | 행사 결과보고서 업로드·검색·새 버전 | 비공개 S3 객체, DB 메타데이터, SQS 처리와 READY 전환, 기존 버전 보존 |
| D-03 | 회계 계정으로 예산·지출·가상 영수증 등록 | 연간 1,000,000원·행사 300,000원·지출 100,000원. 실제 집행 기준 잔액과 검토 상태별 금액 구분(DM-C04) |
| D-04 | 일반 지출 확인과 선생님의 전체 정산 확정 | 확인 권한자의 일반 본인 건 확인 허용, 별도 전체 정산 단계·담당자·시각·이력. 미처리 항목 있을 때 확정 거부, 확정 후 원본 변경 차단 |
| D-05 | 인계자가 보고서·정산을 인수인계에 연결 | 2026 자료 버전·확정 정산·업무 메모가 체크리스트에 표시 |
| D-06 | 승인된 2027 임원이 자료 열람·인수 확인 | 과거 기록 유지, 새 학년도 업무 시작. 기존 임원 권한 종료 후 옛 토큰의 신규 접근 차단 |
| D-07 | 총학생회 계정으로 학과협의회 ID 직접 요청 | API·파일 URL 발급 거부, 검색·집계에서도 비공개 자료가 노출되지 않음 |
| D-08 | 운영 화면과 복구 증거 제시 | CloudWatch 추적 로그·오류 알림, DLQ 재처리·복원 기록, CloudFront 웹과 비공개 원본. 비용·선택/생략 서비스 설명 |

SNS/Step Functions를 구현했다면 승인 알림과 실제 이벤트를 추가로 보여준다. 미구현이면 DB 승인 흐름만 설명하고 알림이 발송되었다고 말하지 않는다. 서비스별 화면을 나열하기보다 사용자 작업 하나가 인증·API·업무 로직·저장소·큐·로그로 이어지는 경로를 설명한다.

발표 자료에는 해결한 문제, 요구와 모델, 실제 배포 구성도, 서비스 선택 이유, 정상·거부 시연, 검증 결과, 출처, 한계·다음 단계를 넣는다. 교수 녹취의 서비스 수·적절성·완성도·연계도·시연 요소를 보존하되 공식 배점이나 최소 서비스 수를 만들지 않는다. 실시간 시연이 어려우면 상세 녹화 시연을 제공할 수 있다는 원문 안내를 활용한다.

## 5. 2027 시범 운영 게이트

아래는 원 대화의 실제 운영 준비 항목을 실행 가능한 점검으로 보완한 제안이다. 과제 시연 성공만으로 충족되지 않는다.

- 학교·조직 도입 범위와 첫 시범 조직, 자료 소유·공유·예산 책임을 합의한다.
- 장기 AWS 계정의 소유자·결제·접근 복구·최고 관리자 승계, 월 비용 상한·알림 수신자를 정한다.
- 가입·임기·중도 교체·퇴임·인수자 승인·조직 관리자 부재 시 대체 절차를 확정한다.
- 개인정보·영수증·감사 이력의 수집·접근·보존·삭제·내보내기 정책, 파일 검사·격리 기준을 확정한다.
- 보안·권한·회계 무결성·복구를 막는 중대 결함을 해결하고 수용 테스트·운영 점검 기록을 남긴다.
- RPO/RTO·백업·복구 책임을 확정하고 DB·파일을 함께 복원하는 훈련을 수행한다.
- 운영·배포·장애 대응·사용자·인수인계 매뉴얼과 코드·계정 관리 책임을 다음 담당자에게 전달한다.

## 6. 검증 결과 기록 양식

실행할 때 아래 열을 가진 기록을 별도 작성한다. 현재 실행 결과는 없다.

| 항목 | 기록할 값 |
|---|---|
| 실행 정보 | 날짜·담당자·커밋/버전·환경·AWS 리전/구성·테스트 데이터 버전 |
| 테스트 결과 | T/D ID, 전제·역할·시각, 기대/실제 결과, 통과/실패/미실행/해당 없음과 이유 |
| 증거 | 명령·요약 로그·스크린샷·녹화·표본 체크섬·복구 기록의 경로. 비밀정보 제외 |
| 후속 조치 | 결함 ID·영향·수정·재검증 결과·결정 목록 변경 |

검증 범위가 로컬이면 로컬로, AWS 통합이면 실제 AWS로 명시한다. 측정 전 성능·복구 목표를 달성했다고 기록하지 않는다.

## 7. 최신 확정사항 연결

T-02는 민감 증빙·개인정보·담당자 연락처의 별도 접근 범위, T-11은 새 책임자의 기존 하위 담당자 목록 유지·검토를 포함한다. AI 확장 X-06 도입 시 Q44의 20문항 중 18개 이상 근거 있는 정답 및 허위 답변·권한 밖 노출 실패 기준과 자료 승인 취소·만료 반영을 검증한다. 해당 업무 코드와 AI는 아직 없어 미실행이다.
