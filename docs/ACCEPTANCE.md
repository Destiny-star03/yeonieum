# 연이음 테스트·시연 기준

버전 0.11 / 2026-11-13, Asia/Seoul. [개발 브리프](DEVELOPMENT_BRIEF.md)의 요구 ID를 참조한다. 사용자 Q1~54·DM-C01/02의 확정 규칙과 보완 테스트 제안(P)을 구분한다. 아래는 전체 수용 기준이며 전 항목의 통과 기록이 아니다. 현재 조직·권한의 API 75개·브라우저 11개 검증 범위는 [프로토타입 가이드](PROTOTYPE.md)에 한정한다. 관계·근거는 [도메인 모델](DOMAIN_MODEL.md)을 따른다. [기능명세서](FUNCTIONAL_SPEC.md)의 필수 M-01~12는 기존 T-01~19와 연결된다. 부가 A·확장 X의 완료 기준은 해당 기능을 도입할 때 추가 검증하며, 미구현 선택 기능을 필수 테스트 통과로 표시하지 않는다.

단계별 완료 판단과 현재/후속 범위는 [프로토타입 완료 기준](PROTOTYPE_COMPLETION.md)에 정리한다.

## 1. 테스트 데이터와 실행 원칙

조직 구조의 근거는 [조직 구조·운영 주체](ORGANIZATION_MODEL.md)다. 현재 기본 단체는 총학생회·학과협의회·신문방송국·연합동아리·모니터링단 5개이며, 모니터링단의 구체 직책은 후속 확인한다. 기존 네 단체의 최고 책임자는 학생회장·의장·국장·연합회장이다. 아래 A/B는 초기 시연용 2개 단체다. 직책 시드는 총학생회·신문방송국의 부장·차장, 학과협의회의 학회장·부학회장·반대표, 연합동아리의 동아리 회장·부회장·총무를 구분한다. 사용 대상은 운영 담당자 중심이며, 구체적인 참여 하위 직책·인원과 자료·회계 기능은 O-02/O-13 결정 후 확정한다. 선생님이 4개 최고 책임자 역할을 부여하고 각 최고 책임자가 자기 단체 하위 역할을 부여하며, 학회장이 부학회장·반대표를 지정하는 체계는 확정사항이다. 의장 계정은 학회장들의 투표로 선출되어 자기 학과 학회장 역할도 겸하며 공식 임기가 동일한 시드로 구성한다(DM-C05).

학생성공센터 담당 선생님은 서비스 관리자 계정으로 포함하고 4개 최고 책임자 역할 부여를 검증한다. 기술 플랫폼 운영권은 별도다. 전체 현황·감사 조회와 전체 정산 확정을 검증하되 일반 자료·민감 증빙의 열람은 분리한다. 일반 지출 본인 확인은 허용하며, 초과분은 해당 단체 최고 책임자, 그 책임자 본인 집행 건은 선생님이 확인한다(DM-C03). 처리 결과·후속 절차는 O-04에서 구체화한다.

- 조직 A: 학과협의회, 조직 B: 총학생회. 운영기: 2026·2027. 학년도·임기 시작/끝은 명시적으로 설정한다.
- 계정: A의 기존 임원, A의 회계 작성자, A의 별도 승인자, A의 새 임원, A의 구성원, B의 임원, 플랫폼 운영자, 미승인 사용자. 일반 본인 확인 허용과 무권한 확인 거부를 검증할 회계 입력+확인 겸임 계정도 사용한다.
- 한 사용자의 A/B 복수 소속, 임기 중간 교체, 만료 직전/직후, 회수된 소속, 다음 학년도 대기 소속을 포함한다.
- 학과→학년→반을 기준으로 같은 반 이름의 다른 학년·학과와 서로 다른 부서·동아리 범위에 대한 허용/거부 사례를 준비한다. 실제 목록·정원은 O-13에서 결정한다. 이름이 같은 총학생회 부장과 신문방송국 부장의 권한이 섞이지 않는지 검증한다. 직책의 상하 연결만으로 권한·결재 단계가 자동 부여되지 않는 제안을 확인한다.
- 파일은 가상 회의록·행사 결과보고서·가상 영수증을 쓴다. 실제 개인정보·은행정보·내부 자료는 넣지 않는다.
- 회계 예시: 연간 예산 1,000,000원, 행사 배정 300,000원, 지출 100,000원. 이 한 건만 실제 발생했고 다른 미처리·정정이 없으면 사용 후 단순 잔액은 연간 900,000원·행사 200,000원이다. 검토 대기·확인 완료·반려 모두 실제 집행액에 포함한다. 환불·정정의 실제 반영 시점은 O-04에서 결정한다. 배정 자체를 지출에 더하지 않는다.
- 핵심 규칙은 단위 테스트, 관계·트랜잭션·권한은 PostgreSQL 기반 API 통합 테스트, 전체 흐름은 브라우저 E2E로 검증한다. 금액·인가·상태 전이의 핵심 실패 사례를 우선한다.
- 테스트 시간은 제어 가능한 시계를 사용하고 실제로 1년을 기다리지 않는다. 실제 AWS 구성은 테스트 계정에서 별도 확인한다. 모의 S3·토큰 통과를 AWS 검증으로 대체하지 않는다.

## 3. 첫 버전 완료 조건 8가지

원문에 세부 항목이 없으므로 아래 8개를 구현 판단 기준으로 제안한다. 기능명세서의 필수 기능·공통 요건과 함께 적용하며, A/X는 도입 범위가 확정된 경우에만 해당 추가 기준을 적용한다. 모두 통과해야 과제용 첫 버전 완료를 제안할 수 있다. 실운영에는 5절 운영 게이트가 추가로 필요하다.

## 4. 발표 시연 순서

6~10분 내 핵심 흐름을 보여주는 초안이며 발표 시간은 수업 안내에 맞춘다. 미리 준비한 가상 데이터를 쓰고 실습 환경에 대비한 녹화본을 함께 준비한다.

| ID | 시연 | 보여줄 결과 / AWS 근거 |
|---|---|---|
| D-01 | 2026 학과협의회 기존 임원 로그인 | Cognito 로그인과 자기 조직·학년도 표시. 임원별 역할 차이 설명 |

SNS/Step Functions를 구현했다면 승인 알림과 실제 이벤트를 추가로 보여준다. 미구현이면 DB 승인 흐름만 설명하고 알림이 발송되었다고 말하지 않는다. 서비스별 화면을 나열하기보다 사용자 작업 하나가 인증·API·업무 로직·저장소·큐·로그로 이어지는 경로를 설명한다.

발표 자료에는 해결한 문제, 요구와 모델, 실제 배포 구성도, 서비스 선택 이유, 정상·거부 시연, 검증 결과, 출처, 한계·다음 단계를 넣는다. 교수 녹취의 서비스 수·적절성·완성도·연계도·시연 요소를 보존하되 공식 배점이나 최소 서비스 수를 만들지 않는다. 실시간 시연이 어려우면 상세 녹화 시연을 제공할 수 있다는 원문 안내를 활용한다.

## 5. 2027 시범 운영 게이트

아래는 원 대화의 실제 운영 준비 항목을 실행 가능한 점검으로 보완한 제안이다. 과제 시연 성공만으로 충족되지 않는다.

- 학교·조직 도입 범위와 첫 시범 조직, 자료 소유·공유·예산 책임을 합의한다.
- 장기 AWS 계정의 소유자·결제·접근 복구·최고 관리자 승계, 월 비용 상한·알림 수신자를 정한다.
- 가입·임기·중도 교체·퇴임·인수자 승인·조직 관리자 부재 시 대체 절차를 확정한다.
- 개인정보·영수증·감사 이력의 수집·접근·보존·삭제·내보내기 정책, 파일 검사·격리 기준을 확정한다.
- 보안·권한·회계 무결성·복구를 막는 중대 결함을 해결하고 수용 테스트·운영 점검 기록을 남긴다.
- RPO/RTO·백업·복구 책임을 확정하고 DB·파일을 함께 복원하는 훈련을 수행한다.
- 운영·배포·장애 대응·사용자·인수인계 매뉴얼과 코드·계정 관리 책임을 다음 담당자에게 전달한다.

## 관리자 보완 수용 기준 (S18, 2026-11-13)

- T-20: 선생님 등록 소속에 운영 단체만 표시한다. 기본 목록은 총학생회·학과협의회·신문방송국·연합동아리·모니터링단이며 신설 단체는 즉시 추가된다. 학과/학년/반은 역할 범위에 보존한다.
- T-21: 단체 생성·중복·삭제는 서버에서 검증한다. 비관리자 호출은 403, 삭제된 단체는 새 역할/등록 대상에서 제외하고 기존 이력은 관리자에게 조회 가능하다. 다른 단체의 계정·역할은 유지한다.
- T-22: 담당자 제거는 선생님만 가능하며 확인 문구 불일치 시 서버 422로 거절한다. 제거한 계정의 기존 세션과 신규 로그인은 실패하고 역할/감사 기록은 재시작 후에도 남는다. 관리자 계정 제거는 거절한다.
- T-23: 숫자 전화번호가 하이픈 형식으로 표시·저장된다. 기존 계정의 유효한 새 역할은 저장되고, 중복/필수 입력 오류는 역할 부여 폼 안에서 확인할 수 있다.

실제 검증: API 75개, Chrome 브라우저 11개. AWS·운영 인증·실제 개인정보 삭제 정책 검증은 포함하지 않는다.

T-24: 삭제한 단체명을 다시 등록하면 같은 ID로 단체·하위 소속이 복원되고 감사에 organization.restored가 남는다. 이전 역할·제거된 계정은 비활성 상태를 유지하며, 운영 중인 이름은 계속 중복 거절한다. 다른 단체의 권한은 영향을 받지 않는다.

T-25: 단체 삭제 확인 창은 ‘단체를 삭제하시겠습니까?’와 확인 문구 입력을 제공한다. ‘삭제하겠습니다’와 정확히 일치해야 버튼을 활성화하고, 직접 API 호출도 불일치 시 422로 거절한다.

T-26: 신규 등록의 학번 숫자 8자리·비밀번호 8자 이상 숫자/특수문자·이메일 형식·소속 1개 이상을 화면과 서버에서 검사한다. 앞자리 0과 중복 없는 복수 소속을 보존한다.

T-27: 로컬 초대 링크는 24시간·1회 사용이며 만료·재발급·계정 제거 시 이전 링크를 거절한다. 신규·복구 계정은 인증 전 로그인 불가다. 수신함·재발급에 현재 관리 범위를 적용하고 토큰을 일반 계정 응답·감사에 노출하지 않는다. 실제 외부 메일 검증을 통과했다고 표시하지 않는다.

T-28: 삭제 계정은 학번+이메일 일치 시 선생님만 같은 ID로 복구하며 새 소속·초대 인증을 적용한다. 다른 이메일/학번 충돌·활성 계정 중복을 거절한다. 과거 역할·이력을 보존하되 이전 역할/세션/초대를 되살리지 않는다. 복수 소속이 역할 권한을 자동 부여하거나 다른 단체 정보 열람을 확대하지 않는다.

T-29: 선생님은 범위에 맞는 모든 기본 역할을 부여하고 종류를 추가·삭제할 수 있다. 학생의 종류 관리·허용되지 않은 하위 조직 생성 API는 거절하며 임의 코드·다른 단체·다른 종류 범위 위조를 차단한다.

T-30: 단체 → 범위 → 역할 순서에 따라 목록이 바뀐다. 부서별 부장/차장과 동아리별 회장/부회장/총무가 구분된다. 등록한 하위 조직·추가 역할을 실제 부여에 사용할 수 있다.

T-31: 종류 삭제는 확인 문구를 검사하고 같은 단체의 현재/예약 부여를 회수한다. 학회장 종류 삭제 시 연결 의장도 종료하며 다른 하위 역할·다른 단체 동명 역할은 유지한다. 재시작·종류 복원으로 과거 권한이 살아나지 않는다.

T-32: 선생님·최고 책임자가 같은 단체의 다른 부서 역할을 명시적으로 추가할 수 있다. 기존 소속을 유지하고 하위 학회장·동아리 회장 등의 재위임/소속 이동 권한을 자동 확대하지 않는다.

T-33: 회수한 역할은 새로고침 후에도 역할 목록에 없고 활동 이력에는 회수가 남는다. 기본 임기 시작/종료가 해당 연도 01-01/12-31이며 저장한 종료 경계는 한국 시간 다음 해 01-01 00시다. 화면은 포함 종료일을 표시하고 종료 경계 직전에는 유효, 경계부터 무효다.

T-34: 학회장이 자기 학과의 학년/반을 만들고 반대표 계정을 등록·초대·역할 부여할 수 있다. 다른 학과 또는 신규 학과 생성을 직접 API로 요청해도 거절한다. 부학회장·반대표의 위임 권한은 확대되지 않는다.

T-35: 학회장/부학회장은 협의회 간부진 및 자기 학과 그룹, 반대표는 자기 학과 그룹에만 참여한다. 유효 역할 회수/종료 시 참여와 하위 조직 생성 권한을 즉시 다시 판정한다. 간부진 명단에 반대표가 없고 그룹 응답에 학번·이메일·전화번호가 없다. 실제 자료실/파일 URL의 공유 접근 검증은 후속이다.

T-36: 선생님이 학회장 카드에서 의장을 지정·해제한다. 동일 계정·학회장 전제·같은 공식 임기·선출 확인을 유지하고 중복 의장은 차단한다. 의장 표시를 위한 중복 카드는 만들지 않으며 의장만 해제해도 학회장은 유지한다.

T-37: 하위 조직 삭제창은 ‘정말로 삭제하시겠습니까?’를 강조하고 삭제 대상·산하 조직 삭제·현재/예약 역할 회수·계정/이력 보존·복원 시 역할 재부여를 안내한다. ‘유의사항을 확인했으며, 삭제하겠습니다.’ 체크 후 삭제 버튼을 눌러야 실행한다. 취소 후 다시 열면 체크를 초기화한다. 서버는 confirmed의 엄격한 불리언 true와 현재 관리 범위를 검사하며 누락·false·문자열·숫자·이전 확인 문구는 422로 거절하고 상태를 변경하지 않는다. 학회장은 자기 학과의 학년/반만 삭제할 수 있고 학과 자체·타 학과·다른 단체 삭제 및 부학회장 요청은 거절한다.

T-40 (S25): 담당자 목록은 유효한 자치단체장부터 표시하고 더보기/접기로 나머지 담당자를 표시/숨긴다. 이름 검색은 기존 부분 일치를 유지하고 단체명 검색은 해당 소속/역할의 조회 가능한 인원을 표시한다. 복수 소속자는 각 단체 검색에 한 번씩 나타난다. 검색은 접힌 담당자를 포함하며 검색어의 앞뒤/내부 공백은 정규화한다. 검색 해제 시 기본 목록으로 복귀하고 결과가 없으면 안내한다. 역할과 임기는 단체 버튼 선택 시 해당 단체만 표시하고 역할이 없는 단체에는 빈 상태를 표시한다. 모바일 가로 넘침이 없고 검색·펼치기로 서버 허용 범위를 넓히지 않는다. 새 브라우저 흐름을 포함한 11개 테스트로 검증한다.
