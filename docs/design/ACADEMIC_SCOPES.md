# 학과협의회·학과 담당자 그룹과 학회장 위임

2026-11-13, S22. 사용자 요청에 따라 학회장·부학회장은 협의회 간부진과 각 학과 담당자 그룹에 동시에 속하고, 반대표는 자기 학과 담당자 그룹에 속한다. 현재 구현은 계정·역할·그룹 표시와 서버 정책이며 실제 자료실은 후속이다.

## 공유 대상과 관리 권한의 분리

| 담당자 | 학과협의회 간부진 자료 대상 | 자기 학과 자료 대상 | 다른 학과 계정·연락처 관리 |
|---|---|---|---|
| 학회장 | 포함 | 포함 | 불가. 의장 겸임 권한은 별도 평가 |
| 부학회장 | 포함 | 포함 | 불가 |
| 반대표 | 제외 | 포함 | 불가 |
| 의장(학회장 겸임) | 포함 | 포함 | 기존 의장 역할의 협의회 관리 범위에 따름 |
| 담당 선생님 | 전체 그룹 조회·관리 | 전체 그룹 조회·관리 | 기존 관리자 범위에 따름 |

그룹은 현재 유효한 기본 역할에서 계산한다. 단순 memberships, 과거 역할, 임기 시작 전·종료·회수·삭제 종류·초대 미인증 계정이나 유사한 이름의 추가 역할만으로 참여시키지 않는다. 반대표는 학과→학년→반 범위에서 판정한다.

`council-officers`는 유효한 학회장·부학회장, `department:<department-id>`는 해당 학과 학회장·부학회장·반대표의 공유 대상이다. 이름·역할·학과와 의장 표시만 그룹 명단에 제공하며 학번·이메일·전화번호를 넣지 않는다. 현재 계정 목록·연락처·역할 관리용 scope/contact_scope는 이 그룹 때문에 확대하지 않는다.

서버의 `can_access_sharing_group`은 매 요청 현재 역할로 대상 여부를 판정한다. 실제 자료실 API와 파일 URL 발급을 구현할 때 문서 상태·민감도·공유 철회 검사와 함께 호출해야 한다. 현재 그룹 표시나 이 정책 함수만으로 실제 문서 업로드·다운로드 기능을 완료했다고 보고하지 않는다. 일반 단체·공통 자료 등 다른 공유 유형은 별도 설계에 따른다.

## 학회장의 자기 학과 업무

학회장은 자기 학과 아래에 학년을, 해당 학년 아래에 반을 등록한다. 예를 들어 1학년→A반과 2학년→B반을 각각 만들고 반대표 계정을 초대·인증한 뒤 해당 범위의 기본 반대표 역할을 부여한다. 표시 이름은 ‘1학년 A반 반대표’처럼 범위가 붙는다. 반마다 새 역할 종류를 만들 필요는 없다.

선생님은 기존대로 모든 조직 구조를 관리한다. 의장은 협의회 학과 하위 학년·반을 관리할 수 있지만 새 학과 자체를 만드는 권한은 선생님에게 둔다(P). 학회장은 자기 학과 밖에 학년·반·담당자를 등록하지 못한다. 부학회장·반대표는 공유 그룹 참여만으로 계정 등록·하위 조직 생성·재위임 권한을 얻지 않는다. 역할 종류 추가·삭제도 선생님만 수행한다.

`/api/workspace`의 `unit_creation_options`가 현재 생성 가능한 상위 조직과 하위 종류를 제공하고 `POST /api/units`는 이를 다시 서버에서 검사한다. 기존 `/api/users`, 초대·역할 부여 API도 현재 범위를 검사한다. UI에 없는 다른 학과 ID를 직접 전송해도 허용하지 않는다.

## 학회장 카드의 의장 표시

선생님은 유효한 학회장 카드의 ‘의장 지정’을 누르고 학회장 투표 선출 확인을 입력한다. 선택한 학회장의 계정·전제 역할·공식 임기를 그대로 사용해 기존 역할 부여 API를 호출한다. 별도 계정이나 새 임기를 입력하지 않는다. 이미 다른 의장이 있으면 먼저 의장만 해제해야 한다.

같은 학회장 카드에 의장 표시를 붙이고 연결된 의장을 별도 중복 카드로 나열하지 않는다. ‘의장 해제’는 기존 역할 회수 화면으로 의장 역할만 종료하며 학회장은 유지한다. 학회장 자격을 회수·종료하면 연결 의장도 종료한다. 학생이 자기 자신을 의장으로 표시하는 기능은 제공하지 않는다.

## 검증

API 75개·브라우저 11개 테스트가 통과했다. 공유 명단과 계정·연락처 범위 분리, 반대표의 간부진 제외, 학회장의 생성·등록·초대·역할 부여, 다른 학과 위조 차단, 역할 회수 후 그룹/생성 권한 종료, 의장 지정·해제와 동일 인물/기간을 검증했다. 자료실 구현 시에는 실제 문서와 파일 URL의 공유 유형별 접근 테스트를 추가해야 한다.

S26: 잘못 등록한 반의 종류 변경은 `POST /api/units/{id}/convert-to-class`로 제공한다. 같은 학과의 활성 학년으로만 이동하며 해당 학과 하위 생성·삭제 권한을 모두 재검사한다. 산하 조직(삭제 이력 포함)이나 역할 이력이 있으면 변경하지 않는다. 기존/삭제 동명 반과 자동 병합하지 않는다. ID·계정 소속을 유지하고 unit.converted-to-class 감사에 before/after를 남긴다. 학년 등록의 1A·3SAP 표기를 거절하고 학과→학년→반 안내를 제공한다. 등록한 반의 선택 편의는 실제 권한 부여와 별개다.
