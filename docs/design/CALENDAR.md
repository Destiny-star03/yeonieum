# 업무 캘린더

월간 연속 스크롤 C: 월간 본문에서 휠·터치 스크롤 또는 빈 칸 마우스 드래그로 주를 이어서 표시한다. 마우스를 아래로 끌면 다음 주가, 위로 끌면 이전 주가 나타난다. 입력이 끝나면 가장 가까운 주의 윗선을 요일 줄 바로 아래에 맞춘다. 화면 중앙 주를 기준으로 월 제목과 작은 달력을 갱신한다. 앞뒤 주를 미리 불러오고 스크롤 중 열린 일정 패널을 유지한다. 기존 일정 막대의 드래그는 일정 이동에 사용한다. CAL-T17로 검증한다.

여러 단체 캘린더 선택 C/P: 새 일정의 단체 메뉴에서 여러 단체 또는 ‘전체’를 선택한다. ‘전체’는 저장 시점에 선택한 등록 가능 단체를 뜻한다. 일정은 한 건으로 저장되며 선택 단체 중 표시된 단체가 있으면 그리드에 한 번 나타난다. 서버는 등록 시 모든 선택 범위를 검사하고, 조회 응답에는 볼 수 있는 범위와 해당 범위의 참여자만 제공한다. 기존 일정 수정·회차 변경·삭제에는 선택한 모든 범위에 대한 수정 권한이 필요하다(P). 기존 공개 범위는 상세 수정으로 변경하지 않으며 단체별 감사 이력을 남긴다. CAL-T16으로 검증한다.

내 캘린더 C: 단체 이름 옆 색상 버튼에서 기본색을 선택하고, 열린 눈·가린 눈 버튼으로 해당 단체 일정을 표시하거나 숨긴다. 기본색 선택은 현재 브라우저에서 계정별로 저장하며(P), 별도 색을 지정하지 않은 일정과 편집 패널의 단체 기본색에 반영한다. 오른쪽 편집 패널은 시각·시간대·반복·참여자·장소·링크·설명·리마인더에 기능 아이콘을 표시한다. CAL-T15로 검증한다.

캘린더 글자 크기 C: 사용자 참고 화면의 글자 비율을 적용한다. 월 제목은 데스크톱에서 최대 22px, 월간 날짜·일정 이름은 12px, 일정 시각은 10px로 표시한다. 편집 제목 입력은 14px, 주요 입력은 13px로 맞추고 작은 화면의 월간 날짜·일정 이름은 11px로 조정한다.

일정 편집 패널 C: 제목·날짜·시간을 우선 표시하고 참여자·장소·설명은 구분선 없이 줄에서 바로 입력한다. 캘린더·상태·정보 표시 여부는 기본 화면에서 바로 조작한다. 링크·첨부 및 리마인더는 메뉴로 열고 등록 개수를 한 줄에 표시한다. 캘린더 메뉴에서 단체와 일정 색상을 함께 선택하며, 상태와 정보 표시는 각각의 메뉴로 조정한다. 종일에는 날짜를 표시하고 종일을 해제하면 입력 시간을 복원한다. 유효하지 않은 링크가 있으면 저장 시 해당 메뉴를 다시 연다. 삭제는 일정 더보기에서 확인한다. CAL-T14로 검증한다.

단체 캘린더 C/P: 선택 목록은 쓰기 권한이 있는 단체당 한 항목이다. 신규 일정은 단체 전체 등록 권한이 있으면 그 단체를 대상으로 하고, 하위 담당 범위만 등록 가능한 경우 해당 단체의 서버가 허용한 범위를 사용한다(P). 기존 일정과 같은 단체로 복사한 일정은 원래 범위를 유지한다. 정보 표시 여부는 상세 또는 시간만 공개를 선택하며 서버가 조회 권한을 검사한다. 화면 오른쪽 패널에서 메뉴는 왼쪽을 우선하고, 여유 공간이 부족한 화면에서는 기준 요소 주변의 화면 안쪽에 표시한다. 브라우저가 선택 메뉴 꾸미기를 지원하면 앱 공통 스타일과 같은 배치를 적용하며 기본 선택 동작을 사용한다.

반복 일정 드래그 확인 C: 화면 중앙 모달에서 기본값인 ‘이 이벤트’ 또는 ‘이 이벤트부터 이후 이벤트’를 선택하고 변경 전후의 날짜·시간을 확인한다. 왼쪽의 빨간 ‘변경 사항 취소’ 또는 Esc는 변경을 버린다. ‘계속 편집’은 캘린더로 돌아가 놓은 위치에 점이 붙은 미저장 회차를 표시한다. 다시 드래그해 위치를 조정하거나 누르면 같은 범위를 선택한 확인 모달을 연다. 저장을 눌러야 서버에 적용한다. 이동·시간 변경·저장·삭제 완료 배너는 표시하지 않는다. 캘린더 글자는 기존보다 1pt 크게 하고, 반복 메뉴의 요일·날짜는 일정 길이와 같은 보조 글자색으로 표시한다. CAL-T13으로 검증한다.

서버 P 계약: 회차 변경은 원래 회차의 시작 시각과 일정 revision을 검사하고, 선택한 범위에 위치·기간 차이를 저장한다. 이후 범위의 순서는 반복 규칙으로 계산한 원래 회차 순서다. 이미 개별 이동한 이후 회차도 동일한 차이만큼 조정한다. 반복 개수·종료일은 원래 규칙에 적용된 뒤 이동하므로 표시 날짜는 원래 종료일을 넘을 수 있다. 원래 회차 키·공개 범위·참여자·자료·리마인더 열람 정책은 유지한다. 일정 상세에서 전체 시리즈의 기본 규칙·기간을 다시 정의하면 새 전체 일정으로 대체하며, 제목·설명만 바꾸면 저장된 회차 이동을 유지한다. 회차 변경 이력은 감사에 기록한다.

2026-11-21 시간 설정 접기 C: 새 일정/다른 일정을 열면 날짜 아래에 ‘종일 · 시간대 · 반복’ 요약 줄을 먼저 표시한다. 마우스를 올리거나 키보드 초점을 두면 리넨 배경으로 강조하고 클릭·Enter/Space로 종일 스위치·시간대·반복을 펼친다. 오른쪽 접기 버튼으로 다시 줄이며 값을 보존한다. 펼치기/접기만으로 수정 상태·서버 저장을 만들지 않는다. 종일은 시간대 선택을 숨기며 해제 시 기존 값을 유지하고, 읽기 전용 일정은 펼쳐서 확인하되 설정은 비활성이다. 모바일도 클릭으로 조작한다. CAL-T12로 검증하며 기존 임시 권한·시간 연동·반복 저장과 로컬 데이터 보존 경계를 유지한다.

2026-11-21 시작 시간 연동 C: 새 시간 일정의 기본 길이는 30분이다. 종료 시각을 직접 바꿔 유효한 길이를 설정하면 이후 시작 시간 변경은 그 길이를 유지해 종료 시간·날짜를 함께 옮긴다. 예: 00:00~01:15에서 시작을 12:00로 바꾸면 12:00~13:15, 23:30으로 바꾸면 다음 날 00:45 종료다. 종료 시간 오른쪽에 기존 리넨 보조 글자색으로 ‘30분’·‘1시간 15분’처럼 표시한다. 시간 목록 선택과 직접 입력에 같이 적용하며 입력 도중의 불완전한 값은 마지막 유효 길이를 보존한다. 기존 저장 일정·복사·시간축 드래그의 명시적 기간은 열기만으로 바꾸지 않는다. 종일의 시간 비활성·날짜 편집, 한국/UTC 시간대, 저장 전 검증·인가·DB는 유지한다. CAL-T11로 검증하며 이번 추가 변경은 로컬에 유지한다.

2026-11-21 공식 일정 연동: 학교 학사일정과 공식 공휴일의 읽기 전용 자동 표시를 추가했다(C). 출처·캐시·권한·24시간 갱신·실패 보존·인증키 경계는 [공식 일정 계약](EXTERNAL_CALENDARS.md)을 따른다. 아래 과거의 ‘외부 동기화 미구현’은 Google/Notion 등 외부 캘린더 양방향 동기화와 외부 알림에 계속 적용하며 이번 공개 자료 수집과 구분한다.

## 빈 공간 선택·요일 반복 보완 (2026-11-21)

사용자 요청 C: 일정 작성/편집 중 달력에서 일정 막대 밖의 빈 공간을 클릭하면 오른쪽 컨텍스트 패널을 기본 단축키 안내로 되돌린다. 저장하지 않은 변경은 기존 폐기 확인을 유지하며 거절하면 입력을 보존한다. 저장/삭제 요청 중에는 닫지 않는다. 일정 막대 선택·우클릭·시간축 드래그 생성은 유지하고, 닫기 클릭을 새 일정 생성으로 중복 처리하지 않는다. 모바일에서 달력 빈 곳을 선택할 수 있을 때도 기본 패널을 유지한다.

반복 선택은 ‘반복하지 않음·매일·평일 월~금·매주 해당 요일·격주·매월 같은 날짜·매월 몇 번째 요일·매년·사용자 지정’ 팝업이다. 사용자 지정은 1~12 일/주/개월/년 간격, 주간의 복수 요일, 월간의 같은 날짜/몇 번째 요일, 계속 반복/날짜까지/1~1000회 후 종료를 지원한다. 취소/Escape는 원래 반복 설정을 유지하며 완료는 편집창에만 반영한다. 실제 저장은 일정 추가/변경 저장을 눌러야 한다.

서버 P 계약: weekdays는 일=0~토=6의 중복 없는 주간 요일 목록이다. 생략한 과거 주간 일정은 시작일 요일을 유지한다. 주 간격은 시작일이 속한 일요일 시작 주를 기준으로 계산하고 시작일보다 앞선 회차를 만들지 않는다. 선택 요일이 시작일과 다르면 첫 일치 요일부터 표시한다. monthly_mode=weekday는 시작일의 1~5번째 요일이며 해당 요일이 없는 달은 건너뛴다. 기본 date는 기존 날짜/윤년 건너뛰기를 유지한다. count는 첫 실제 회차를 포함한 전체 시리즈 회차 수이며 조회 기간마다 다시 세지 않는다. until과 count는 동시에 사용할 수 없다. 종료일은 기존처럼 선택 시간대 기준 포함 날짜이며 종일은 한국 시간이다. 반복 단일 회차 수정·외부 동기화는 추가하지 않았다.

새 필드는 기존 details JSON 안에 저장하며 DB 초기화·이전 일정 일괄 변환은 없다. RepeatPicker.tsx가 빠른 메뉴·사용자 지정 창을, recurrence.py가 회차 계산을 맡는다. DatePicker 팝업은 사용자 지정 모달 안에서도 조작할 수 있도록 해당 열린 dialog 안에 렌더링한다. 기존 인가·마스킹·참여자/자료·리마인더와 시리즈 수정·삭제 경계를 유지한다.

2026-11-21 색상 선택 보완 C: 기존 텍스트 선택 목록을 색상 점 팔레트 팝업으로 바꾼다. 현재 단체·단체 기본색 복귀, 색 이름과 선택 체크를 제공한다. 기존 default/sand/stone/ink/clay 값을 유지하고 빨강·주황·노랑·초록·민트·하늘·파랑·보라·분홍을 추가했다. 리넨 화면 테마는 유지하며 사용자 지정 일정 표시 색만 확장한다. 저장된 색은 기존 details JSON으로 보존하고 서버 허용 목록을 검사한다. 월간/주간/일간 표시·복사·반복의 기존 저장 경계를 유지한다. 팝업은 스크롤 영역 밖에서 화면 안에 배치하며 방향키로 이동, Enter/Space로 선택, Escape·바깥 클릭으로 닫고 선택/Escape 시 입력 버튼으로 초점을 돌린다. 읽기 전용 일정에는 색 변경을 허용하지 않는다.

2026-11-17. 사용자 요청 C: 대시보드의 담당자 요약·역할 차트·담당 범위/연락처 표 영역을 제거하고, Notion Calendar와 비슷하게 일정을 추가·삭제하는 캘린더를 배치한다. 리넨 색상과 기존 업무 진입 카드를 유지한다. Notion 서비스 연동은 요청 범위가 아니다.

2026-11-19 후속 작업: 기존 미커밋 코드의 노션형 편집 패널·반복·참여자·링크·자료 연결·리마인더·드래그 기능을 이어서 검증·보완했다. 아래 추가 정책은 로컬 구현을 위한 P이며 자료실 인터뷰의 답변이나 운영 승인으로 취급하지 않는다.

## 구현과 사용

월간(6주)·주간·일간 보기, 이전/다음 기간·오늘/지정 날짜 이동, 작은 달력과 단체별 표시 필터를 제공한다. 날짜 또는 ‘일정 추가’를 눌러 오른쪽 패널에서 제목·공유 범위·시작/종료·종일·장소·메모를 입력한다. 일정을 눌러 상세·수정·삭제하며 삭제는 확인 뒤 실행한다. 모바일에서는 편집 패널과 일정 목록으로 전체 제목·시간·단체를 확인한다. 패널 열기·캘린더 확대, 우클릭 메뉴의 복사·붙여넣기, 명령어 메뉴(Ctrl/Cmd+K)와 단축키를 제공한다.

보기 설정에는 3/4/5/7일 범위, 주말 숨김·주 번호·12/24시간·밀도·한국 시간/UTC를 둔다. 3/4/5일은 선택일에서 시작하는 연속 날짜이며 주말 숨김 시 표시 열 수는 줄어든다. 설정은 해당 브라우저에 저장한다. 시간축의 빈 구간 드래그로 새 일정 기간을 고르고 기존 일정을 옮기거나 아래 손잡이로 종료 시간을 변경할 수 있다. 날짜·시간 입력으로도 같은 변경을 할 수 있다.

2026-11-19 사용자 화면 요청 C: 편집 패널은 시작 시간 → 종료 시간·일정 길이를 한 줄에 표시하고 그 아래에 시작/종료 날짜를 둔다. 종일을 켜면 시간 줄을 비활성 표시하고 날짜를 나란히 편집한다. 날짜는 리넨 색상의 둥근 월 선택창에서 이전/다음 달·오늘·키보드 방향키로 선택하며 종료일은 시작일보다 앞설 수 없다. 반복 종료일에도 같은 선택창을 쓴다. 시간은 24시간 형식의 직접 입력과 15분 간격 스크롤 목록을 제공하며 종료 시간 목록에 시작부터의 기간을 표시한다. 종일 전환 중 입력한 시간은 유지하고 종일 저장 경계·한국 시간/UTC·기존 권한은 그대로 유지한다. 선택창은 패널 스크롤에 잘리지 않도록 화면 안에 배치하고 Escape·바깥 클릭으로 닫는다.

서버 SQLite의 calendar_events와 calendar_reminder_reads에 저장하며 재시작/새로고침 후 유지한다. 확장 필드는 details JSON에 저장하고 기존 테이블에는 이 열만 기본값과 함께 추가한다. 기존 데이터는 초기화하지 않는다. 빈 캘린더에 예시 일정을 자동 생성하지 않는다.

## 임시 업무 권한 (P)

세부 권한은 이번 구현을 위한 임시 정책이며 역할 관리·자료실·회계 권한을 변경하지 않는다.

- 유효한 학생 담당자는 현재 scope의 조직·하위 범위에 일정을 등록한다. 계정 소속만 있거나 예약/종료·회수 역할만 있으면 등록할 수 없다.
- 열람은 현재 scope와 그 상위 조직의 일정이다. 예: 반대표는 자기 반과 자기 학년/학과/단체의 공통 일정을 보지만 다른 반·학과 내부 일정을 보지 못한다. 단순 상위 공통 일정 열람은 수정·삭제·역할 위임 권한을 주지 않는다.
- 현재 담당 범위 안의 작성자와 해당 범위 최고 책임자·의장·학회장이 수정/삭제한다. 작성자라도 역할을 잃으면 옛 권한으로 관리하지 못한다.
- 선생님은 활성 단위 전체의 일반 업무 일정을 관리한다. 민감 첨부·자료실 권한과 구분한다.
- 기존 일정의 소유 범위는 변경하지 않는다. 제목·기간·종일·장소·메모와 아래 반복·참여자·링크·자료 참조·표시·리마인더 설정을 수정한다.
- 조직 삭제 시 캘린더 조회 범위에서도 제외하지만 일정을 물리 삭제하지 않는다. 조직 기록·계정·역할 이력을 연쇄 삭제하지 않는다.

## 반복·참여자·자료·표시 정책 (P)

- 반복은 일/주/월/년, 간격 1~12, 선택 종료일을 지원한다. 월의 31일·윤년 2월 29일처럼 해당 날짜가 없으면 그 회차를 건너뛴다. 회차는 같은 일정 ID와 서로 다른 instance_key를 사용한다. 상세 수정·삭제는 전체 시리즈에 적용한다. 드래그 이동과 종료 시간 변경은 확인 모달에서 선택한 회차 범위에 적용한다. 반복 종료일은 선택한 시간대 기준 포함 일자다. 종일 일정은 한국 시간 기준이다.
- 참여자는 해당 일정 범위를 현재 열람할 수 있는 활성·인증 담당자 중에서 선택한다. 참여자 선택 목록은 일정 등록 범위에서만 제공한다. 상위 공통 일정을 읽는 것만으로 그 범위의 담당자 선택 목록을 열람할 수 없다. 이름·ID만 제공하고 연락처는 추가 공개하지 않는다. 역할 회수·비활성화 후 참여자 이름·ID를 응답에서 제외하지만 저장된 과거 연결은 보존한다.
- 링크는 사용자 입력 http/https 주소이며 외부 초대·동기화가 아니다. 자료 첨부는 현재 열람 가능한 일반 자료실 자료의 참조다. 원본을 복제하거나 참여자에게 열람 권한을 추가하지 않는다. 목록·상세에서 현재 자료 권한을 검사하고 다운로드 API도 다시 검사한다. 권한을 잃은 참조는 응답에서 숨기고 과거 저장 연결은 유지한다. 현재 버전을 연결하며 정산의 불변 증빙 연결로 취급하지 않는다.
- 시간만 공개 옵션은 작성자·현재 참여자·일정 관리권자에게 상세를 제공하고 나머지 허용된 열람자에게는 ‘바쁨’과 시간만 표시한다. 설명·장소·링크·참여자·첨부는 검색·목록·상세에서 함께 숨긴다. 바쁨/한가함과 색상은 표시 옵션이고 다른 업무 권한을 부여하지 않는다.
- 시작 전 리마인더는 0~10080분, 최대 3개다. 포털이 열린 동안 작성자·참여자의 현재 열람 범위에서만 표시하고 확인 기록을 서버에 남긴다. 기본 확인 주기는 1분이며 이메일·OS 푸시·앱이 닫힌 동안의 전송을 구현한 것이 아니다.

## 시간·상태·감사

UTC 정규화 시각을 저장하고 시간 일정은 Asia/Seoul(UTC+9) 또는 UTC로 입력·표시한다. 종일 종료일은 한국 시간으로 화면에서 포함한 뒤 다음 날 자정으로 저장한다. 기간은 [시작, 종료)이며 자정이나 월말·연도를 넘는 일정은 겹치는 모든 날짜에 표시하고 종료 경계 다음 날에는 표시하지 않는다.

revision과 expected_revision으로 동시 수정·삭제 충돌을 409로 거절한다. 삭제는 confirmed의 엄격한 불리언 true가 필요하며 deleted_at/deleted_by와 감사 이력을 남기는 운영 제외다. 생성·수정·삭제와 감사 기록은 같은 트랜잭션이다. 과거 일정의 모든 수정 전 원문을 복원하는 기능이나 일정 휴지통 UI를 구현한 것으로 표현하지 않는다.

API: GET /api/calendar/options, GET/POST /api/calendar/events, GET /api/calendar/events/{id}, POST /api/calendar/events/{id}/update, POST /api/calendar/events/{id}/remove. 목록은 시간대가 있는 최대 93일의 겹치는 일정만 요청하고 권한 필터를 적용한다. 권한 밖 상세 ID는 404다. 로그인과 변경 출처 검사를 기존 API와 공유한다.

추가 API: GET /api/calendar/search(현재 열람 가능한 제목·설명·장소, 최대 50개), GET /api/calendar/editor-options(참여자·자료 선택), GET /api/calendar/reminders, POST /api/calendar/events/{id}/reminder-read. 참여자 지정이나 연결 자료가 일정 자체의 범위를 넓히지 않는다.
