# 연이음 내부 알림

로그인한 포털 상단의 종 버튼에서 읽지 않은 알림 수를 확인한다. 최신 자료·일정 공유 알림 최대 50개와 현재 확인 가능한 캘린더 리마인더를 함께 표시한다. 항목을 누르면 읽음으로 처리하고 원본 화면을 연다. 별도의 체크 버튼은 원본을 열지 않고 읽음 처리한다. 포털은 30초마다, 알림함을 열거나 브라우저 탭에 돌아올 때 다시 조회한다.

## 수신 범위와 저장

- 자료 등록과 새 버전 업로드가 성공하면 등록자를 제외한 현재 열람 가능 담당자에게 알림을 기록한다. 개인 보관은 대상에서 제외한다. 공유 범위 변경으로 새로 열람할 수 있게 된 담당자에게도 알림을 기록한다.
- 일정이 등록되면 공유 캘린더 범위와 현재 단체 역할이 맞는 담당자에게 알린다. 기존 일정에 참여자가 추가되면 새 참여자에게 알린다. 본인이 올린 자료와 본인이 공유한 일정은 단체 공유 알림으로 표시하지 않는다. 본인이 설정한 리마인더에는 기존 작성자·참여자 규칙을 적용한다.
- 자료·일정 공유 알림은 원본을 저장하는 트랜잭션에서 `notifications`에 기록한다. 수신자·종류·원본 ID·발생 키 조합을 중복 금지로 설정한다. 알림에서 보이는 제목과 단체명은 조회 시 원본 권한을 다시 검사한 뒤 가져온다. 접근 권한이 끝났거나 원본이 삭제되면 목록에서도 빠진다. 시간만 공개하는 일정은 기존 캘린더와 같이 `바쁨`으로 표시한다.
- 기존 자료·공유 일정의 알림은 일괄 생성하지 않는다. 리마인더는 캘린더의 회차별 날짜 계산과 서버 읽음 기록을 공유한다. 확인한 리마인더는 목록에서 사라지고 자료·공유 일정은 읽은 상태로 남는다.

## AWS SQS 연동 검토

SQS는 업로드나 일정 공유 뒤의 알림 생성·전송을 워커로 넘길 때 사용할 수 있다. PostgreSQL에 업무 변경과 발행 대기 이벤트를 한 트랜잭션으로 기록하고, 별도 발행기가 커밋된 이벤트의 ID만 SQS에 전달한다. 워커는 원본 권한을 재검사하고 지금과 같은 고유 키로 알림을 생성한다. 표준 큐는 중복 전달 가능성이 있으므로 워커를 멱등하게 만들고 반복 실패는 DLQ로 보낸다. 알림 내역과 읽음 상태의 저장소는 PostgreSQL이다. [AWS Transactional outbox](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html) · [SQS DLQ](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-dead-letter-queues.html)

일정 리마인더를 포털이 닫힌 동안에도 예약해 처리하려면 EventBridge Scheduler가 해당 시각에 SQS 작업을 전달할 수 있다. 워커는 일정 변경·삭제와 접근 권한을 재검사하고, 별도의 이메일이나 웹 푸시 채널을 붙일 때 그 채널의 수신 동의를 적용한다. 현재 구현은 포털 내부 알림이다. [EventBridge Scheduler 예약 유형](https://docs.aws.amazon.com/scheduler/latest/UserGuide/schedule-types.html)
