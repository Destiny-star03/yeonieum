# 단체별 역할 종류와 범위 우선 역할 부여

2026-11-13, S20. 사용자 확정: 선생님의 역할 종류 추가·삭제, 담당 범위 우선 선택, 부서별 부장·차장, 동아리별 회장·부회장·총무. 아래의 권한·삭제·복원 세부 방식은 이를 구현한 P 선택이며 실제 학교 규정 승인을 뜻하지 않는다.

## 현재 동작

역할 부여는 단체 → 담당 범위 → 역할 → 대상 담당자 → 임기 순서다. 선생님은 운영 중인 범위에 맞는 모든 역할을 부여할 수 있다. 직접 API 호출에서도 단체·단위 종류·현재 역할 종류 상태·초대 인증·계정·임기·중복·의장 자격을 검사한다. 본인의 역할은 변경하지 못한다.

| 단체 | 전체 범위 | 하위 단위와 기본 역할 |
|---|---|---|
| 총학생회 | 학생회장 | 각 부서: 부장·차장 |
| 학과협의회 | 의장 | 각 학과: 학회장·부학회장 / 학과→학년→반: 반대표 |
| 신문방송국 | 국장 | 각 부서: 부장·차장 |
| 연합동아리(동아리연합회) | 연합회장 | 각 동아리: 동아리 회장·부회장·총무 |
| 모니터링단·신설 단체 | 최고 책임자(가상 시연용 기본 이름) | 선생님이 부서·역할을 구성. 구체 실제 직책은 후속 확인 |

실제 부서·동아리 이름은 임의로 채우지 않는다. 선생님이 ‘하위 조직·역할 종류 관리’에서 상위 조직과 이름으로 등록한다. 학회장은 자기 학과의 학년·반을 등록할 수 있다(S22). 학과협의회는 학과→학년→반, 연합동아리는 동아리, 나머지는 부서 구조를 지원한다. 동일 상위 조직의 같은 종류·이름은 중복 거절하며 다른 단체·학년의 같은 이름은 구별한다. 하위 조직 삭제는 S23에서 제공한다. 하위 조직 이름 변경은 후속이다.

## 저장과 권한 경계

`role_definitions`는 id, org_id, code, label, scope_kind, builtin, active를 가진다. 부여 기록은 기존 assignments의 role code를 유지하고 조회 시 단체별 이름을 연결한다. 같은 ‘부장’도 총학생회·신문방송국의 정의가 다르다. 기본 역할은 기존 code를 보존해 마이그레이션하고, 추가 역할의 code는 서버가 생성한다. 이름을 ‘의장’이나 ‘관리자’로 만든다고 선출 자격·관리자 권한을 얻지 않는다.

선생님만 역할 종류를 추가·삭제한다. 기존 최고 책임자·의장은 자기 단체의 추가 역할을 부여할 수 있고, 학회장은 자기 학과 범위 안에서만 추가 역할을 지정한다(P). 추가 역할을 받은 사람은 그 이름만으로 다른 사람의 역할을 부여하거나 계정·단체·회계를 관리할 수 없다. 동아리 회장의 하위 역할 재위임도 자동 부여하지 않는다.

등록 소속과 부여 범위는 구분한다. 같은 단체의 다른 부서 겸임은 선생님·해당 최고 책임자가 명시적으로 역할을 부여할 때 세부 소속을 추가한다. 기존 다른 소속은 유지한다. 하위 학회장은 기존 소속이 일치하는 자기 학과 담당자만 지정하며 다른 학과 담당자를 임의로 자기 학과로 이동시키지 못한다. 다른 단체의 새 역할은 그 단체 소속 없이는 허용하지 않는다.

## 삭제와 복원

역할 종류 삭제 창은 ‘삭제하겠습니다’를 입력해야 진행한다. 해당 단체·역할 종류를 비활성화하면서 현재·예약 부여를 모두 회수하고 감사에 기록한다. 학회장 종류 삭제 시 그 자격에 연결된 의장도 종료한다. 다른 단체의 동명 역할·다른 하위 담당자·계정·과거 감사는 삭제하지 않는다.

같은 단체에서 같은 이름·범위 종류로 재추가하면 기존 정의를 복원한다. 이전 부여의 revoked_at은 유지한다. 서버 재시작과 기본값 시드도 삭제 상태를 되살리지 않는다. 역할 종류 삭제는 그 역할을 없애는 것이므로 담당자 한 명의 ‘역할 회수’와 영향을 구분해야 한다.

## API와 검증

- `POST /api/units`: 선생님의 하위 조직 등록 및 학회장·의장의 허용된 학과 하위 학년/반 등록.
- `POST /api/role-types`: 종류 추가 또는 삭제 상태의 같은 정의 복원.
- `POST /api/role-types/{id}/remove`: 종류 삭제·해당 부여 회수·의장 자격 연쇄 종료.
- `/api/workspace`: 범위별 grant_options, 역할 정의·이름·종류를 제공한다. 삭제된 정의는 관리자 과거 이력 조회를 위해 보존한다.

API 75개·브라우저 11개 테스트로 기본 흐름과 추가 규칙을 검증한다. 실제 학교 인증·메일 발송·회계·문서·AWS 실행은 이번 구현 범위가 아니다.

S21 표시·임기 보완: 회수된 assignments는 조회 응답과 DB에 보존하지만 ‘역할과 임기’ 카드 목록에서는 필터링한다. 자동 입력은 학교 시간대의 연도 기준 01-01~12-31(포함)이다. UI 종료일은 다음 날 한국 시간 00시의 배타적 ends_at으로 변환하며 표시는 ends_at 직전 시각의 날짜를 사용한다. 의장은 연결된 학회장 timestamps를 그대로 쓰고 기존 데이터는 일괄 변경하지 않는다.

## 하위 조직 삭제·복원 (S23)

`POST /api/units/{id}/remove`는 S24에 따라 `confirmed: true`(엄격한 불리언)와 `can_remove_child_unit`을 검사한다. 누락·false·문자열·숫자·종전 확인 문구는 상태 변경 없이 422로 거절한다. 화면은 강조된 경고와 삭제/복원 유의사항, 필수 체크박스를 제공하고 체크 후 별도 삭제 버튼으로 실행하며 매번 다시 동의받는다. 단체·계정·역할 종류의 기존 확인 문구는 그대로 유지한다. 이 권한은 해당 조직의 상위에서 생성할 수 있는 범위와 같다. 단체 루트는 기존 단체 관리 API를 사용하며 학회장은 자기 학과 루트를 삭제할 수 없다. workspace의 unit_deletion_options가 표시 가능한 삭제 버튼을 정하지만 서버도 매번 검사한다.

선택한 하위 구조를 비활성화하고 현재·예약 부여를 모두 회수한다. 학회장 전제 종료의 연결 의장은 구조 밖 협의회 역할이어도 종료한다. users/memberships/assignments/audit는 물리 삭제하지 않는다. 일반 관리 scope에서 비활성 하위 단위를 제외한다.

`units.deletion_root_id`로 삭제 묶음을 기록한다. 이미 비활성인 하위 구조의 표식을 덮어쓰지 않는다. 단체·하위 조직 복원은 그 삭제 묶음만 활성화하며 기존에 별도 삭제된 가지는 유지한다. 기존 비활성 단위는 과거 단체 삭제에 따른 조직 ID로 비파괴 마이그레이션한다. 동일 부모·종류·이름 재등록은 200/restored=true, 신규는 201/restored=false다. 복원은 역할을 재활성화하지 않는다. unit.removed/unit.restored 및 역할 회수 감사가 남는다.
