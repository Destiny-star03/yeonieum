# 로컬 예산·정산·인수인계 구현 계약

## 지출결의서 제출·검토

예산 화면에서 행사 배정 영역과 신규 지출의 행사 선택을 제거한다. 새 결의서는 선택한 단체·연도의 연간 예산에 기록된다. 기존 행사 연결·예외 처리·확정 정산 데이터 및 기존 행사 API는 호환성을 위해 보존한다. 예전 지출의 상세에서 연결된 행사명을 볼 수 있다.

로컬 화면은 실제 지출 1건을 결의서 1건으로 취급한다. 제목·지출 목적·집행일·금액·실제 집행자를 입력하고 거래처/지급처, 결제 수단과 증빙을 추가할 수 있다. 새 결의서의 제목·거래처·결제 수단은 지출 ID를 참조하는 `expense_resolutions`에 저장된다. 기존 JSON·multipart 요청의 `resolution` 객체와 정정 요청의 `resolution`·`resubmit` 필드는 선택 사항이다. 증빙 없이 제출하면 같은 상세에서 나중에 첨부할 수 있다.

결의서 목록에서 전체·검토 대기·승인·반려를 필터링하고 제목·목적·집행자·거래처를 검색할 수 있다. 상세에서 증빙, 반려 사유와 제출·검토·정정·재제출 이력을 확인한다. 기존 `review` 권한은 승인 또는 사유를 남긴 반려에 사용한다. 기존 `record` 권한으로 반려된 결의서를 보완해 같은 지출 ID로 재제출하면 상태가 검토 대기로 바뀐다. 최신 리비전을 확인해 동시 변경을 차단한다. 실제 집행액은 최초 제출 시 반영되고, 승인·반려·동일 금액 재제출만으로 잔액이 바뀌지 않는다. 금액을 정정하면 차이만 반영한다. 증빙과 초과분의 기존 권한 및 확정 정산 잠금 규칙을 적용한다.

## 예산 현황과 잔액 그래프

예산·정산 상단에서 단체·연도를 바꾸고 현재 잔액과 연간 예산의 사용·잔액·초과 구간을 확인한다. 날짜별 그래프는 현재 장부 기준으로 집행일 순서에 따라 다시 계산한 잔액이며, 최근 지출일 최대 7개에서 각 날짜의 마지막 잔액을 보여준다. 그래프의 날짜를 선택하면 해당 잔액을 표시한다. 초과 잔액은 0원 아래에, 지출이 없는 단체는 빈 상태로 표시한다. 지출 등록은 상단에서 열고, 목록에서는 선택한 지출 바로 아래에서 증빙과 검토 정보를 확인한다.

## 영수증 첨부와 지출 상세 (2026-11-24)

‘예산 · 정산’에서 단체·연도를 선택하고 지출결의서 금액을 입력한다. 아래 ‘영수증 첨부’에서 파일명과 PDF·사진 미리보기를 확인하고 저장 전에 교체하거나 빼며, 제출 버튼 근처에서 차감 후 예상 잔액을 확인한다. XLSX·CSV 합계 자동 입력은 이 흐름에서도 사용할 수 있다.

새 지출에 파일이 있으면 `POST /api/budgets/expenses/submit`에 `multipart/form-data`로 `expense` JSON 필드를 먼저 보내고 `receipt` 파일 한 개를 뒤에 보낸다. 회계 권한·금액·단체·연도·행사를 확인하고, 서버가 50 MiB 이하의 파일 형식과 내용을 검사한다. 지출·증빙 연결이 같은 DB 트랜잭션에서 완료될 때 잔액에 한 번 반영한다. 요청 ID와 파일이 같은 제출을 재시도하면 기존 지출을 돌려준다. 실패한 지출이나 증빙은 함께 취소하고 저장 중 만든 파일을 정리한다. 증빙 없는 지출은 기존 JSON 요청으로 기록하고, 기존 지출의 증빙은 상세에서 별도로 첨부할 수 있다.

목록에서 ‘증빙 N개’ 또는 ‘첨부 없음’을 확인한다. 지출을 열면 ‘첨부 증빙’을 바로 조회하고 같은 상세 주소를 새로고침할 수 있다. 서버는 각 요청에서 현재 단체와 증빙 권한을 검사한다. PDF·PNG·JPEG는 미리보기 응답을 제공하고 원본 다운로드는 모든 허용 형식에서 사용할 수 있다. 응답에는 비공개 저장 경로를 포함하지 않는다.

학습 경로는 웹의 `features/budgets/BudgetWorkspace.tsx`와 `ExpenseDialog.tsx`, API의 `modules/budgets/router.py`, 증빙 저장·응답의 `modules/budgets/evidence.py`, 공용 파일 기록의 `modules/documents/storage.py` 순이다. `expense_evidence.expense_id`가 지출과 연결되며 불변 파일은 무작위 `storage_key`로 저장한다. SQLite 기본은 `local-data/prototype-evidence/`, PostgreSQL은 `YEONIEUM_STORAGE_ROOT/evidence/`다.

## 운영 v1 지출 금액 입력과 증빙 (2026-11-24)

사용자가 확인한 v1 방식(C)은 담당자의 금액 확인, 원본 증빙 첨부, ‘지출 기록’ 저장 후 잔액 차감이다. 사진·PDF 영수증, HWP·HWPX 및 DOCX 결의서는 비공개 증빙으로 첨부하고 실제 결제액을 직접 입력한다. 필요한 경우 지출을 먼저 기록하고 증빙을 나중에 첨부한다. AI·OCR을 이용한 금액 제안은 후속 기능으로 검토한다.

XLSX·UTF-8 CSV를 첨부하면 서버가 표의 용도·금액 열을 읽고 합계·소계 행을 제외해 합계를 계산한다. 빈 금액 칸은 합계로 채우고 직접 입력한 금액은 유지한다. 미리보기에서 행과 합산 기준을 확인하거나 합계를 직접 적용할 수 있다. 파일을 빼거나 바꾸면 이전 파일에서 채운 금액을 지운다. 파일을 읽을 수 없어도 직접 금액을 입력하고 증빙으로 첨부할 수 있다.

저장 전에는 예상 차감액을 표시하고, 저장할 때 최종 확인한 금액을 지출 1건으로 기록한다. 신규 지출과 함께 선택한 원본 증빙은 위 계약에 따라 함께 저장한다. 개별 검토와 전체 정산 확정은 기존 절차를 따른다. [수용 기준 T-54·55](../ACCEPTANCE.md)

## 단체 연간 예산·증빙 등록 보완 (2026-11-21)

사용자 화면 보완 C: 예산 단체 카드를 드래그해 표시 순서를 바꾼다. P 저장 범위는 계정별·현재 브라우저의 localStorage이며 모든 사용자에게 적용되는 서버 공통 조직 순서는 아니다. 카드와 단체 선택 목록에 함께 적용하고 연도를 바꿔도 유지한다. 손잡이는 마우스/터치 드래그와 방향키 이동을 지원하며 선택한 단체·예산·권한은 바꾸지 않는다. 저장된 ID는 현재 API 허용 단체와만 결합하고 새 단체는 뒤에 붙인다. 손상된 설정은 기본 순서로 돌아가며 저장 제한은 이번 화면에서만 유지됨을 알린다.

이 절은 아래 11월 16일 P 설명 중 충돌하는 부분보다 우선한다. 사용자 요청 C는 담당자의 단체별 연간 예산 설정, 단체 책임자의 영수증·엑셀·지출결의서 등록과 사용액·차감 내역 표시다. 담당자를 담당 선생님으로 해석하고, 다음 세부는 로컬 구현 선택 P로 적용했다.

- 선생님은 별도 자기 권한 설정 없이 단체별 연간 예산을 편성한다. 학생의 기존 명시적 편성 권한은 유지한다. 단체 카드에서 연간 예산·사용액·잔액·지출 건수·확정 여부를 확인하며 학생에게는 현재 회계 열람 권한이 있는 단체만 반환한다.
- 선생님의 예산 저장창에 기본 선택된 ‘현재 단체 책임자에게 지출·증빙 등록 권한 함께 부여’를 제공한다. 명시적으로 저장하면 현재 최고 책임자·의장의 역할 ID에 `view`, `record`, `evidence`를 연결하고 각각 감사 기록을 남긴다. 선택 해제는 신규 부여를 생략하며 기존 권한을 회수하지 않는다. 권한은 단체 단위이며 저장한 연도에만 한정되지 않는다. 역할 종료 후 새 책임자에게 자동 승계하지 않는다. 개별 검토·예산 편성 권한과 선생님의 증빙 권한은 별도다.
- 지출 등록창에서 파일을 끌어 놓거나 선택하고 집행일·금액·용도·실제 집행자·행사를 확인한다. 파일은 기존 50 MiB 및 형식 검사를 유지한다. 증빙이 없어도 실제 지출을 먼저 보존할 수 있고 나중에 첨부한다. 사진·PDF·한글/Word 지출결의서의 금액은 직접 입력하며 OCR·진위 판정은 구현하지 않았다.
- XLSX 또는 UTF-8 CSV의 ‘용도/내역/적요’와 ‘금액/지출금액/사용금액/집행금액’ 열을 미리 읽는다. 5 MiB, 압축 해제 10 MiB, 최대 500개 지출 행·64열·첫 20행 안의 헤더로 제한한다. XLSX는 첫 표시 시트의 저장된 값만 읽고 지출 셀의 수식은 거절한다. 합계·총계·총합계·소계 행은 중복 합산하지 않는다. 금액은 양의 정수 원화여야 하며 암호·매크로·XML 선언 엔터티를 거절한다. CSV 양식 내려받기를 제공한다. 기존 XLS는 XLSX/UTF-8 CSV로 변환해야 한다.
- 파일 선택·미리 읽기는 장부나 파일 저장소를 변경하지 않는다. 읽은 합계와 실제 지출을 확인하고 날짜·집행자·용도를 입력한 뒤 ‘지출 기록’을 누른다. 파일당 확인한 금액 하나를 지출 1건으로 기록하고 원본을 비공개 증빙으로 보존한다.
- 기존 지출에 증빙을 별도로 등록할 수 있다. 별도 첨부의 성공·실패는 이미 저장된 실제 지출액을 바꾸지 않는다.
- 지출 목록은 집행일 최신순이며 각 행에 ‘차감 전 잔액 − 금액 = 차감 후 잔액’을 표시한다. 이는 현재 예산·현재 정정 금액을 집행일 순서로 다시 계산한 표시다. 당시 통장 잔액 또는 등록 시점의 확정 잔액이 아니다. 검토 대기·확인·반려는 실제액을 상태별로 분해하며 한 번 더 차감하지 않는다. 초과 지출 보존·책임자/선생님 예외 처리와 정산 확정 잠금은 유지한다.

서식 구조 참고: [Microsoft SpreadsheetML](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document). 새 외부 라이브러리·AI·AWS·메일 서비스는 연결하지 않았다. 기존 DB·일반 자료·민감 증빙을 보존한다.

2026-11-16. 1차 **로컬 시연**을 위해 M-07~11의 핵심 흐름을 추가했다. 기존 사용자 확정사항(C)을 적용하고 아래 운영 세부는 임시 구현 선택(P)으로 둔다. 실제 학교 회계 규정·개인정보 정책·AWS 검증의 완료를 뜻하지 않는다.

## 예산·지출 권한

- 단체 연간 예산과 행사 배정은 정수 원화로 저장한다. 학과·동아리 독립 장부는 없다. 행사 배정 합계는 연간 예산 이하여야 한다. 예산을 낮춰 실제 지출이 초과되어도 실제 지출을 지우거나 예산을 자동 증액하지 않는다.
- 선생님이 단체별로 `view`(회계 상세 열람), `plan`(편성), `record`(지출·정정), `review`(개별 확인·반려), `evidence`(민감 증빙 등록·열람)를 명시적으로 지정한다(P). 학생은 `view`와 해당 작업 권한이 모두 필요하다. 부여 시의 유효 역할 ID에 묶이므로 그 역할 종료 후 다른 역할을 다시 받아도 이전 회계 권한이 부활하지 않는다. 선생님 자신의 입력·검토·증빙 권한도 별도 설정한다. 선생님의 전체 현황 조회·정산 확정 권한은 C다.
- 지출의 등록자와 실제 집행자를 분리한다. 집행자는 해당 단체의 유효 역할 담당자다. 집행일과 기록 연도는 같은 해여야 한다(P). 지출은 실제액·현재 검토 상태로 보존하며 반려돼도 합계에서 빠지지 않는다. 행사 지출은 연간 실제액에 한 번만 포함한다.
- 지출 등록은 작성자별 요청 ID로 중복 제출을 한 건으로 처리한다. 같은 요청 ID로 다른 내용이 오면 409를 반환한다. 화면은 저장과 결과 새로고침이 모두 끝날 때까지 요청 ID를 유지한다.
- 현재 지출액 합계에서 연간 잔액과 행사별 잔액을 계산한다. 검토 대기·확인·반려액은 실제액의 상태별 분해이며 추가 차감하지 않는다. 정정은 금액·용도의 전후값과 사유를 남기고 검토를 다시 대기시킨다.
- 지출을 등록한 순서의 누적 실제액이 연간 또는 해당 행사 배정액을 넘으면 그 지출에 초과분 확인을 요구한다(P). 해당 단체의 현재 최고 책임자가 처리한다. 실제 집행자가 등록 당시 또는 확인 시점의 최고 책임자라면 선생님이 처리한다(P). 등록자는 판단 기준이 아니다. 예외 결과와 개별 검토는 별도다. 반려 후 환불·감액 반영의 학교 절차는 O-04 미결정이므로 자동 금액 변경은 없다.
- 영수증은 일반 자료실과 분리된 비공개 `local-data/prototype-evidence`에 불변 파일로 보관한다. 50 MiB와 자료실의 형식 기본 검사를 재사용하며 실제 악성코드 검사라고 주장하지 않는다. 단체 회계 보기 권한만으로 증빙 내용을 내려받을 수 없다. 파일 내용 실존·거래 진위는 확인하지 않는다.
- 선생님은 모든 지출의 개별 검토·초과분 처리·증빙 등록이 끝난 뒤 전체 정산을 확정한다. 확정 시 현재 상태와 합계를 불변 스냅샷으로 남기고 원본 지출·예산·증빙 변경을 잠근다. 확정 뒤 정정·재확정은 학교 규칙 O-04 결정 후 별도 기록 방식으로 추가한다. 현재 화면의 정정은 **확정 전**에만 동작한다.

## 인수인계

- 인계 묶음은 단체·기록 연도·현 담당자·후임 담당자를 참조한다. 현재 인계자와 같은 단체의 현재 또는 예정 역할을 가진 후임만 지정한다. 운영기 모델은 아직 독립 엔터티가 아니다.
- 인계자·단체 최고 책임자·선생님이 업무 메모, 본인이 열람할 수 있는 자료실 자료 ID, 확정 정산 ID를 항목으로 추가한다. 인계 항목은 원본 자료·정산을 복제하지 않는다.
- 후임이 역할이 유효해진 뒤 자기 계정으로 필수 항목을 확인한다. 인계자가 대리 작성해도 확인할 수 없다. 필수 항목 미확인 시 완료를 거절한다. 묶음 완료와 역할 부여·회수는 별도 감사 사건이다. 후임 역할 승인·구임원 회수는 조직·권한 화면에서 명시적으로 수행한다.
- 역할 종료·계정 비활성화·단체 삭제 후 과거 묶음·자료·지출·감사는 DB에 보존된다. 현재 역할이 없으면 화면과 API 접근은 거부된다.

## 백업·제약

`python -m yeonieum.modules.documents.backup`의 로컬 별도 폴더 복사는 SQLite·일반 자료 파일·민감 증빙 파일을 함께 검증한다. 기존 DB·파일을 덮어쓰지 않는다. 가상 DB마다 `<DB이름>-files`와 `<DB이름>-evidence`를 사용한다. 자동 백업, 동시 외부 변경 대비 일관성 보증, AWS 복원 훈련은 후속이다.

현재 구현은 단체 간 회계 공유, 환불·확정 후 정정, 영수증 진위 판정, 운영 학년도/회계연도 경계, 학교 인증·실제 이메일, AWS 연결을 포함하지 않는다. 첫 버전 전체 수용 기준 T-07~15의 통과로 표시하지 않는다.
