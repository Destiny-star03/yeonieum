# 담당자 등록·복구·로컬 초대 인증

2026-11-13. 현재 구현은 루프백 전용 가상 자료 시연이다. 사용자 답변에 따라 실제 메일 발송 서비스는 아직 연결하지 않고 로컬 수신함에서 흐름만 검증한다. 학교 학적·재직 확인과 이메일 실존 확인은 구현하지 않았다.

## 등록 조건과 여러 소속

- 신규 학생 계정의 학번은 ASCII 숫자 8자리이며 앞자리 0을 보존한다. 기존 가상 시드 로그인 ID와 교직원 계정은 이 신규 학생 등록 조건으로 변경하지 않는다.
- 비밀번호는 8~128자, ASCII 숫자와 특수문자(Unicode 문장부호·기호)를 각각 하나 이상 포함한다. 문자 포함은 별도 필수 조건이 아니다. 서버에서 검사하고 Argon2 해시만 보관한다.
- 이메일은 일반적인 ASCII 주소 형식을 검사하고 앞뒤 공백 제거·소문자 비교를 적용한다. 도메인 라벨은 문자·숫자·하이픈과 길이를 검증한다. 같은 이메일의 대소문자는 이 포털에서 동일하게 취급한다. 형식 검사는 주소 존재나 소유 증명이 아니다.
- `POST /api/users`의 `unit_ids`는 중복을 제거한 1개 이상 소속 목록이다. 선택된 모든 소속의 현재 관리 권한을 한 트랜잭션에서 검사한다. 관리자 등록은 운영 단체만, 하위 책임자는 부여 가능한 소속만 선택한다.
- 소속만으로 업무 권한을 주지 않는다. 한 단체의 미배정 소속을 첫 세부 역할로 구체화할 때 다른 단체 소속은 유지한다. 다른 단체의 소속 정보와 등록 감사 상세는 해당 단체 조회 범위를 넘겨 노출하지 않는다.

## 삭제 계정 복구

학번과 이메일이 모두 일치하는 비활성 학생 계정은 선생님만 같은 사용자 ID로 복구할 수 있다. 한 항목만 일치하거나 이미 운영 중이면 409로 거절한다. 관리자 계정 복구는 학생 등록 API로 제공하지 않는다.

복구 시 입력한 이름·전화번호·임시 비밀번호·소속 목록을 적용한다. 선택하지 않은 과거 소속은 현재 소속에서 제외하지만 이전 역할·감사 참조는 보존한다. 기존 세션·초대 링크는 무효화하고 새 초대를 발급한다. 과거 업무 역할은 되살리지 않으며 새 초대 인증 전에는 로그인할 수 없다.

## 로컬 초대 인증

1. 신규·복구 계정은 `email_verified=0`으로 생성한다. 로그인과 역할 유효 판정에서 인증 대기 상태를 차단한다. 역할을 미리 기록해도 인증 전에는 사용할 수 없다.
2. 32바이트 난수 기반 링크를 발급하고 24시간 만료·1회 사용을 검사한다. 검증 테이블에는 토큰 해시를 저장한다. 로컬 수신함에는 메일 내용에 해당하는 링크가 있으므로 실제 메일함처럼 비밀로 취급한다. 해당 SQLite 파일은 Git에서 제외하며 토큰·비밀번호·전체 링크는 감사 로그에 남기지 않는다.
3. `GET /api/invitations/outbox`는 관리자 또는 발급 당시 작성자이면서 현재 모든 대상 소속을 관리할 수 있는 담당자에게만 표시한다. 실제 발송 대신 개발용 로컬 링크를 표시한다.
4. 링크 토큰은 URL fragment에 넣어 웹 서버 접근 경로·쿼리 로그에 포함시키지 않는다. 페이지를 열기만 해서는 인증하지 않고 사용자가 버튼을 눌러 `POST /api/invitations/accept`를 호출한다. 성공 후 주소에서 토큰을 지운다.
5. `POST /api/users/{id}/invite`는 현재 대상 소속 관리 권한을 다시 검사하며 1분 간격으로 재발급할 수 있다. 재발급 시 이전 링크는 무효화한다. 사용·만료·삭제 계정의 링크는 거절한다.
6. 계정 제거는 미사용 초대도 폐기한다. 인증 완료는 로그인 허용일 뿐 업무 역할을 새로 부여하지 않는다. 신규 수신자에게는 별도의 임시 비밀번호 전달 절차가 필요하며 메일에 비밀번호를 넣지 않는다.

기존 데모·로컬 계정은 DB 마이그레이션 시 호환을 위해 `email_verified=1`을 기본으로 유지한다. 이는 실제 메일 확인 이력이 아니며 운영으로 승격할 인증 근거로 사용할 수 없다. 운영 전에는 별도 재인증·초기 관리자 지정과 학교 확인 정책을 정해야 한다.

## 실제 이메일 연결 전에 남은 일

SMTP/SES 등 발송 서비스와 검증된 발신 주소, 외부에서 접근 가능한 HTTPS 초대 주소, 발송 실패·반송·재발송 처리와 개인정보 보관 정책을 정한다. 실제 주소 확인은 초대 수신자의 링크 인증으로 판정해야 하며 DNS·주소 형식만으로 실존을 확정하지 않는다. 현재 로컬 인증 완료는 실제 메일 수신을 증명하지 않는다.

참고: [OWASP 이메일 검증 지침](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html). 이 지침을 구현 범위에 맞게 적용했으며 운영 인증을 완료한 것으로 해석하지 않는다.
