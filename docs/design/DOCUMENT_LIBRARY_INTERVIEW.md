# 자료실 기능명세 인터뷰

2026-11-16 / 상태: 초안·사용자 답변 대기. 명세를 함께 확인한 뒤 Figma 화면 설계를 진행한다.

## 요청과 진행 원칙

사용자는 자료실의 역할과 상세 기능을 먼저 명세하고, 그 결과로 Figma를 그리기를 요청했다. 설치된 grilling 스킬의 설계 트리·라운드 방식으로 진행하며 질문·권장안·답변·후속 결정을 분리한다. 아래 권장안은 답변 전 확정사항이 아니다. 코드 변경·데이터 이전·커밋·푸시는 이번 인터뷰의 시작 작업에 포함하지 않는다.

현재 구현 계약은 [DOCUMENT_LIBRARY.md](DOCUMENT_LIBRARY.md), 전체 요구는 [개발 브리프](../DEVELOPMENT_BRIEF.md), [기능명세](../FUNCTIONAL_SPEC.md), [권한](../ACCESS_CONTROL.md), [수용 기준](../ACCEPTANCE.md)을 따른다. 다른 CLI 작업의 코드·문서·미커밋 변경을 보존한다.

## 기존 사용자 합의로 유지할 전제

- 담당자가 바뀌어도 조직의 기록은 남고 다음 담당자가 과거 자료를 다시 요청하는 일을 줄인다(Q7/14).
- 우선 파일 보관·분류·검색·버전 보존에 집중한다(Q8).
- 파일 상한은 50 MiB다(Q17). 큰 영상·압축자료 등은 실제 수요 확인 후 범위를 정한다.
- 일반 자료 열람만으로 영수증·개인정보 첨부 열람을 허용하지 않는다(Q24). 민감도별 세부 권한은 아직 별도 결정 대상이다(Q15).
- 관리에는 새 버전·메타데이터 수정·휴지통·복원이 포함된다(Q25). 삭제 이력과 과거 기록을 보존하고 확정 회계 증빙은 별도 제한한다(Q16/25/30).
- 현재 유효한 역할과 소속 범위를 서버에서 검사한다. 학과협의회 간부진과 학과 담당자 공유 대상은 구분한다(S22).
- AI는 후속이다. 승인된 지식 자료만 별도 대상으로 정하고 영수증·학번·전화번호·내부 개인정보를 자동 포함하지 않는다(Q33~44).

## 현재 구현과 미확정 정책의 구분

2026-11-16 현재 일반 자료실의 로컬 업로드·검색·분류·인증 다운로드·버전·휴지통·복원 구현이 존재한다. 학년도·폴더·종류·행사는 문자열 분류이며 실제 폴더 트리나 마감 운영기를 의미하지 않는다. 일반 자료실과 민감 회계 증빙 저장은 분리되어 있다.

작성자/범위 책임자의 관리, 선생님의 명시적 일반 자료 범위 자기 설정, 공유 대상의 상세 선택, 현재 파일 형식·표시 방식은 구현 중 적용한 P다. 이를 사용자 확정사항으로 취급하지 않는다. 최신 코드의 자세한 읽기 전용 사실 조사를 별도로 진행한다. 이 문서는 새로운 테스트 통과를 주장하지 않는다.

## 설계 트리

1. 사용 범위: 자료 종류 / 작업 중 자료 포함 여부 / 기본 탐색 / 학교 공용 공간
2. 1의 답변 이후: 소유 조직과 세부 공유 대상 / 역할별 등록·열람·관리 / 민감 문서 경계
3. 1~2의 답변 이후: 공개·승인·최종본 상태 / 버전·정정 / 후임 접근·마감·보존·휴지통
4. 정책 확정 이후: 업로드 필수값 / 목록·상세·검색·빈 상태 / 실제 문서 3~5개 업무 시나리오
5. 공유 이해 확인: 기능 ID·권한표·상태 전이·수용 기준·미결정과 후속 범위 정리
6. 명세 확인 이후: 기존 연이음 테마의 Figma 자료실 목록·등록·상세/버전·공유/권한·휴지통 화면

사용 목적과 제외 범위, 사용자별 업무 시나리오, 필수/부가/확장 기능, 역할별 열람·등록·수정·공유·삭제·복원 표, 분류와 소유권 모델, 문서/버전/승인 상태 전이, 화면별 입출력·오류·완료 기준, Figma 화면 목록을 합의와 연결한다. 답변을 받으면 관련 DL 결정 ID와 연결하고 기존 기능/수용 ID를 보존한다.

## 읽기 전용 사실 조사 보완

자료실 API·웹과 문서를 별도 조사했다. 실제 로컬 구현이 존재하지만 이번 인터뷰에서는 테스트를 실행하지 않았다. 선생님의 일반 자료 자기 권한 설정, 모든 유효 학생 역할의 등록/열람, 작성자/범위 책임자의 관리, 단일 공유 대상, 소유 범위 이동 불가, 후임의 과거 자료 관리와 세부 버전 복원 방식은 P다. 특히 현재 공유 대상은 복수 대상 목록이 아닌 하나라서 간부진과 여러 학과에 동시에 공유하려는 요구와 차이가 생길 수 있다.

일반 자료실의 민감도 분류·승인/마스킹은 없고 회계 증빙은 별도 로컬 기능에 존재한다. 따라서 전체 증빙·회계·인수인계가 미구현이라는 과거 인계문을 현재 사실로 사용하지 않는다. 일반 자료실과 증빙의 연결·전환, 단체 간 일반 공유, 본문 검색/OCR/미리보기, 실제 폴더 트리·운영기 마감, 실제 악성코드 검사·AWS는 현재 구현과 구분한다. 기존 문서의 과거 미구현 문장은 최신 2026-11-16 보완과 실제 코드로 해석하되 이번 인터뷰에서 임의로 덮어쓰지 않는다.

## 참고 이미지 UI 요청으로 작업 범위 보완

사용자가 현재 리넨 색상을 유지하면서 첨부 참고 화면처럼 기존 기능을 배치하도록 요청했다. 이를 공통 워크스페이스 UI의 구현 승인으로 적용한다. 앞선 학년도/상시 자료 제안 및 DL-Q1~4 답변은 아직 확정되지 않았으므로 자료실의 분류·권한·승인 정책을 임의로 바꾸지 않는다. 피그마 산출물을 만들었다고 보고하지 않는다. 구체 UI는 [WORKSPACE_UI.md](WORKSPACE_UI.md)에 기록한다.
