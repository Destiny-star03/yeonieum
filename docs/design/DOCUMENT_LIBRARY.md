# 일반 자료실 로컬 구현

## 등록 UX 보완 (2026-11-21)

사용자 요청 C: 인터넷의 UX 원칙과 파일 서비스 사례를 조사해 입력을 줄이고 드래그 업로드를 제공한다. [Hick의 법칙](https://lawsofux.com/hicks-law/)의 선택 복잡도와 [NN/g 점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/)를 참고해 제목·공개 범위·파일을 기본 화면에 두고 행사·분류·설명·태그·버전 메모는 ‘추가 정보’로 접었다. 보관 위치·연도는 현재 위치에서 가져오고 ‘위치 변경’에서 편집한다. 사용자 테스트로 UX 개선 효과를 측정했다고 표현하지 않는다.

[Google Drive](https://support.google.com/drive/answer/2424368?hl=en)의 폴더로 드래그하는 흐름과 [Carbon](https://www.carbondesignsystem.com/building-blocks/core/components/file-uploader/guidelines)·[GOV.UK](https://design-system.service.gov.uk/components/file-upload/)의 드롭 영역+파일 선택 버튼·파일명/크기·오류 피드백을 참고했다. 리넨 색상·기존 글꼴을 유지하고 새 라이브러리는 추가하지 않는다.

- 파일을 놓거나 고르면 제목을 확장자 없는 파일명으로 채운다. 직접 편집한 제목은 파일 교체로 덮어쓰지 않는다. 자료 종류를 비우면 ‘일반 자료’를 사용한다.
- **선택됨**과 실제 저장을 구분한다. 파일명·크기를 확인하고 ‘파일 등록’을 눌러야 서버에 저장한다. 파일 선택 후에는 드롭 영역을 줄여 확인/등록에 집중한다. 실제 전송률을 측정하지 않는 가짜 진행률은 표시하지 않는다.
- 드래그 강조, 교체·제거, 키보드/모바일 선택을 지원한다. 제거 후 선택 버튼에 포커스를 돌린다. 창 밖에 파일을 놓아 브라우저가 이동하는 동작을 막는다.
- 한 번에 1개, 1바이트~50 MiB다. 빈 파일·크기 초과·미지원 확장자·다중/폴더 드롭은 즉시 안내하고 잘못된 새 선택은 기존 선택을 해제한다. 서버의 내용·크기·체크섬 검사와 권한·공유 범위는 유지한다.
- 업로드/저장 결과 재조회 동안 변경·중복 등록을 막는다. 저장 후 목록 갱신 실패 시 재전송 없이 결과 확인만 재시도한다. 실제 파일·DB를 초기화하지 않는다.
- 구현은 FileDropzone(선택·드래그·검증)과 UploadDialog(메타데이터·명시적 저장)에 둔다. 기존 분류·공유 수정 화면은 상세 항목을 유지한다.

## 최신 연도·단체·개인 보관·폴더 계약 (2026-11-20)

사용자 변경 C: **연도 → 단체 → 폴더·파일**로 탐색하며 **개인 보관(작성자만)**과 **단체 공유**를 구분한다. 시작 화면은 연도/단체 카드와 최근 자료, 폴더 안은 보관함 메뉴·파일 목록·오른쪽 상세 패널이다. 이 절이 아래의 이전 P 정책과 충돌하면 우선한다.

- 연도는 기존 학년도 분류 값(1900~2200)이며 역할 임기와 별개다. 올해와 열람 가능한 파일/폴더의 연도를 제시하고 다른 연도도 열 수 있다. 기존 파일·버전·공유 범위는 자동 변경하지 않는다.
- `private`는 작성자 본인만 열람·버전·분류·휴지통·복원을 수행한다. 선생님·책임자의 관리권도 타인의 개인 파일/폴더 열람을 허용하지 않는다(C). 위치를 고르지 않은 새 자료의 기본은 개인 보관이며 폴더 안에서는 폴더의 공유 방식을 따른다(P 안전 기본값).
- `organization`은 같은 단체에 현재 유효한 역할이 있는 담당자에게 열람을 허용한다(P: 단체 공유의 담당자 판정). 단순 계정 소속으로 허용하지 않는다. 선생님은 기존 명시적 일반 자료 범위 설정이 있어야 공유 자료에 접근한다. 공유 파일의 수정은 기존 작성자·범위 책임자 정책을 유지한다. 공유 수신자에게 계정·연락처·회계 관리권을 주지 않는다.
- 기존 `unit`·협의회 간부진·학과 담당자 공유 자료는 원래 권한을 유지한다. 화면에 ‘범위 한정 공유’로 표시하고 단체 공유 자료함에서도 허용된 자료만 보인다.
- 개인 자료도 활성·인증 계정과 해당 단체의 현재 역할을 요구한다(P). 선생님의 개인 자료는 본인의 명시적 자료 범위 안에서 사용한다. 역할/계정/조직 종료로 접근을 잃어도 파일·버전은 삭제하지 않으며 후임에게 개인 자료를 자동 승계하지 않는다. 임기 종료 후 개인 파일 이용·회수와 보존 기간은 운영 결정 후 구체화한다.
- 실제 폴더는 연도·단체·공유 방식·작성자·상위 폴더를 저장한다. 같은 위치/이름은 중복 거절하고 개인 폴더 이름 공간은 작성자별이다. 하위 폴더·파일은 상위의 연도·단체·공유 방식을 따른다. 타인의 개인 폴더 ID나 다른 단체·연도·공유 방식을 위조한 요청은 거절한다. 공유 폴더에는 해당 단체 담당자가 자신의 허용된 담당 범위로 파일을 등록한다.
- 폴더 밖의 개인 파일은 작성자가 명시적으로 단체 공유로 바꿀 수 있다. 다른 관리자가 타인의 공유 파일을 개인 보관으로 바꿀 수 없다. 폴더 안의 연도·공유 방식은 고정한다. 폴더 공유 변경·이동·이름 변경·삭제는 이번 프로토타입에서 제공하지 않으며 파일 휴지통·복원은 유지한다.
- DB에 `document_folders`와 documents의 nullable `folder_id`를 추가한다. 기존 문자열 `folder`는 ‘분류 태그 (기존 폴더 분류)’로 보존하고 폴더 자동 생성·병합·파일 이동은 하지 않는다. DB와 모든 버전 파일을 함께 보존한다.
- 카드/목록 전환, 파일 형식(PDF/TXT·CSV/DOC·HWP/PPT/XLS/이미지), 수정 날짜·이름·크기 정렬, 검색·페이지·경로 탐색을 제공한다. 카드 그림은 **파일 형식 표시**이며 실제 본문 썸네일·문서 편집·미리보기는 아니다. 320/390px에서는 보관함을 상단 탭으로, 상세를 목록 아래로 배치한다. 외부 드라이브·기기 저장공간 연결은 없다.
- 개인 폴더 이름과 개인 파일 제목·설명은 일반 관리 감사 상세에 남기지 않고 식별자·공유 방식·연도 등 동작 정보만 남긴다. 개인 자료도 목록·검색 건수·상세·버전·다운로드·업로드 완료에서 현재 권한을 검사한다. 일반 자료와 민감 증빙은 계속 분리한다.

추가 API: GET/POST `/api/documents/folders`는 조직·연도·공유 방식으로 폴더 목록/중첩 생성을 제공한다. metadata의 `folder_id`는 실제 폴더 ID 또는 null이다. 목록은 `folder_id=root` 또는 폴더 ID, `audience=all|private|organization`(organization은 허용된 기존 제한 공유도 포함), `file_type=pdf|text|document|slides|sheet|image`, `sort=updated|name|size`, `descending=true|false`를 받는다. 폴더 필터 생략 시 모든 위치에서 기존처럼 권한 내 검색한다. options는 현재 열람 가능한 `years`도 제공한다.

구현은 API documents/folders.py·policy.py·router.py·schema.py, 웹 documents/DocumentLibrary·FolderDialog·LibraryFiles와 기존 등록/상세 컴포넌트에 둔다. API 자료실 28개(개인 격리·명시적 공유·중첩·위조·중복·역할 회수·추가 마이그레이션·감사 원자성), 브라우저 자료실 6개(기존 기능과 연도/단체/폴더·개인/공유·모바일)를 검증한다. 실제 실행 결과는 PROTOTYPE.md를 따른다.

## 이전 일반 자료실 구현 기록 (2026-11-16)

2026-11-16. 사용자 요청으로 M-04~06의 일반 자료 업로드·분류·검색·다운로드·버전·휴지통·복원을 구현했다. 기존 조직·권한 시연에 연결하며 회계 증빙·실데이터·AWS·AI는 포함하지 않는다. 아래 권한·형식·저장 세부는 **P 임시 선택**이며 O-01/03/08/09의 운영 정책 확정이 아니다. 권한 질문의 답변은 아직 수신하지 않아 권장안을 적용했다.

## 권한과 공유

| 주체 | 일반 자료 열람·등록 | 분류·공유·새 버전·휴지통·복원 |
|---|---|---|
| 유효한 학생 담당자 | 현재 역할의 담당 범위 및 하위 범위에 등록·열람. 지정 공유 그룹 자료는 추가 열람 | 현재 범위 안의 본인 작성 자료 |
| 최고 책임자·의장·학회장 | 현재 담당 범위 | 그 범위의 자료 관리 |
| 선생님 | 서비스 관리자라는 이유만으로 파일 자동 열람 없음. 자료실의 단체별 ‘자료 권한 설정’으로 명시적 범위 설정 | 설정한 단체의 일반 자료 관리. 설정·해제 감사 기록 |
| 미인증·비활성·역할 미부여 학생 | 불가 | 불가 |

소속만으로 접근 권한을 주지 않는다. 서버가 세션·계정·인증·현재 역할·기간·단체/범위 상태를 검사한다. 작성자도 역할 종료 후 옛 권한을 유지하지 않는다. 후임 책임자는 기존 자료 ID·버전으로 이어받고 계정 제거는 자료를 삭제하지 않는다. 단체 삭제 시 명시적 선생님 자료 권한도 해제하며 단체 복원으로 되살리지 않는다.

자료의 소유 범위는 변경할 수 없다. 기본 열람 대상은 해당 담당 범위이며 학과협의회에서는 `council-officers`와 해당 `department:<id>`를 선택할 수 있다. S22의 `can_access_sharing_group`을 실제 목록·상세·버전·다운로드에 적용한다. 학회장/부학회장은 협의회 간부진+자기 학과, 반대표는 자기 학과 대상이다. 공유 수신자는 원본을 수정·재공유하지 못한다. 소유 범위 책임자는 관리와 기록 보존을 위해 계속 접근한다. 다른 학과 대상을 위조할 수 없다. 단체 간 공유는 O-01 확정 후 추가한다.

선생님의 일반 자료 자기 범위 설정 역시 임시 시연 정책이다. 운영에서는 승인 주체·별도 업무 권한·관리자 부재 절차를 확정해야 한다. 민감 자료 열람은 이 설정으로 허용하지 않는다. 일반 자료실에는 민감 자료 유형·증빙 연결·AI 포함 기능이 없으며 파일 내용에서 개인정보를 자동 탐지한다고 주장하지 않는다.

## 파일·상태·무결성

- 1바이트~50 MiB(52,428,800바이트). 파일 이름·확장자·기본 내용 서명, 실제 전송 크기와 SHA-256을 서버가 검사한다. UTF-8 TXT/CSV, PDF, PNG/JPEG, DOCX/XLSX/PPTX, HWP/HWPX를 보관한다.
- 텍스트는 UTF-8·NUL 거절, PDF/이미지/HWP는 기본 헤더, Office/HWPX는 ZIP 구조의 필수 항목·암호화·매크로·총 확장 크기를 확인한다. 포맷 전체의 유효성이나 악성코드 검사가 아니다. 본문 파싱·미리보기·OCR·압축 파일 일반 업로드는 제공하지 않는다.
- `PENDING → PROCESSING → READY | REJECTED`. 준비 요청은 30분·1회 사용이다. 전송 중 권한·기간·자료 상태가 바뀌면 완료 직전에 다시 거절한다. 실패하면 새 파일을 제거하고 자료/버전을 공개하지 않는다. 만료·서버 강제 종료의 미완료 세션은 다시 등록한다. 이미 커밋한 파일은 자동 삭제하지 않는다.
- 저장 위치는 DB 파일과 같은 폴더의 `<DB이름>-files`다. 기본은 `local-data/prototype-files`. 서버가 생성한 불투명 키만 사용하며 원래 파일명은 DB 메타데이터다. 웹 public·Git에 파일을 넣지 않는다.
- 다운로드는 세션이 필요한 API 스트림이다. 매 요청 권한·자료 상태·크기·체크섬을 확인하고 attachment와 no-store로 반환한다. 공개 정적 URL·장기 서명 URL은 발급하지 않는다. 이미 내려받은 사본은 회수할 수 없다.
- v1→v2 등록 후 v1 파일 복원은 v3을 생성한다. 기존 바이트와 버전은 유지한다. `revision`으로 오래된 수정/동시 버전 충돌을 거절한다. 휴지통은 목록·다운로드에서 제외하며 관리자가 복원할 수 있다. 영구 삭제·자동 만료 삭제는 없다.
- 문서 변경과 감사는 같은 SQLite 트랜잭션으로 저장한다. 다운로드 감사는 접근 허용 사실이며 사용자의 열람 완료 증명이 아니다. 파일 쓰기 뒤 DB 실패 시 새 파일은 정리한다. 프로세스 강제 종료 시 남을 수 있는 미참조 파일의 자동 정리는 후속이다.

학년도는 분류 값이며 역할 임기와 분리한다. 폴더·행사·자료 종류는 검색 가능한 문자열 분류다. 별도 폴더 트리·행사 업무 엔터티·마감 운영기는 후속이다. 회계 증빙은 [별도 민감 저장·권한](LOCAL_FINANCE_HANDOVER.md)을 적용하며 일반 자료실 파일을 자동 증빙으로 취급하지 않는다.

| GET `/api/documents` | 제목·설명·파일명, 단체·학년도·종류·폴더·행사·휴지통 필터, 권한 필터 후 건수·페이지 |
| POST `/api/documents/uploads` | 새 자료 메타데이터 또는 자료 ID+현재 revision, 파일명·크기·SHA-256 |
| GET `/api/documents/uploads/{id}` | 발급자의 현재 권한 내 처리 상태 |
| PUT `/api/documents/uploads/{id}/content` | 파일 바이트 전송·검증·버전 저장 |
| GET `/api/documents/{id}` | 허용된 자료와 버전 목록 |
| POST `/api/documents/{id}/metadata` | 소유 범위를 유지한 분류·공유 수정 |
| POST `/api/documents/{id}/trash`, `/restore` | 휴지통·복원 |
| POST `/api/documents/{id}/restore-version` | 과거 파일을 새 버전으로 복원 |
| GET `/api/documents/{id}/versions/{version}/download` | 매 요청 재인가·파일 무결성 확인 후 다운로드 |

목록 한 페이지 기본 20개·상한 100개. 타 범위 자료는 상세·버전·변경·다운로드에서 동일 404로 처리한다. 업로드는 403/422/413, 변경 충돌은 409다. 직접 SQL 조회 방식이므로 대규모 문서 수의 성능 목표 N-04는 아직 미측정이다.

## 백업·복원

서버를 종료한 상태에서 실행하는 로컬 수동 절차다. DB와 모든 참조 버전 파일, 회계 증빙 파일을 함께 복사하고 복사본의 크기·체크섬을 재검증한다. 파일 외부 수정과 전송 중인 요청이 없는 상태를 사용한다. 대상은 **존재하지 않는 새 폴더**여야 하며 현재 DB를 덮어쓰지 않는다.

```powershell
$env:PYTHONPATH = 'apps/api/src'
.\apps\api\.venv\Scripts\python.exe -m yeonieum.modules.documents.backup backup --database local-data/prototype.sqlite3 --destination local-data/library-backup-20261116
.\apps\api\.venv\Scripts\python.exe -m yeonieum.modules.documents.backup restore --database local-data/library-backup-20261116/prototype.sqlite3 --destination local-data/library-restored-20261116
$env:YEONIEUM_DB_PATH = 'D:\Tak\yeonieum\local-data\library-restored-20261116\prototype.sqlite3'
```

검증 후 별도 API 프로세스에서 복원 DB로 실행한다. 원래 DB로 돌아가려면 서버를 종료하고 `Remove-Item Env:YEONIEUM_DB_PATH -ErrorAction SilentlyContinue` 후 원래 명령으로 실행한다. 실패한 백업은 완료본이 아니며 원본 오류를 해결한 뒤 새 대상에 다시 수행한다. 백업은 계정·초대 링크도 포함하므로 Git·공개 경로 밖에 보관한다. 자동 스케줄·원격 백업·보존 기간·RPO/RTO·AWS 복구 훈련은 미구현/미검증이다.

## 검증과 구현 위치

API의 `modules/documents`와 웹의 `features/documents`에 기능을 묶었다. `test_documents.py`는 형식/크기/체크섬, 조직 격리, 그룹 공유, 역할 회수와 전송 중 재검사, 버전·휴지통·동시 수정, 감사 실패 원자성, 계정/조직 종료 후 보존, 재시작과 별도 백업 복원을 검증한다. `documents.spec.ts`는 데스크톱/모바일의 실제 파일 등록·다운로드·버전·복원·검색·선생님 범위 해제를 검증한다. 실제 학교 자료는 사용하지 않는다.

로컬 전체 API 96개(자료실 21개), 브라우저 15개(자료실 4개), Git 정책 12개를 통과했다. 전송 중 로그아웃/세션 만료, 파일 저장 성공 후 화면 갱신 실패의 중복 등록 방지, 마지막 페이지 감소 보정도 회귀 검증했다. 새 원격 CI는 커밋·푸시하지 않아 실행하지 않았다. API TestClient의 기존 httpx 사용 중단 예정 경고 1개는 별도 의존성 전환 때 처리한다.

요청 스트리밍과 첨부 다운로드는 [Starlette Requests](https://starlette.dev/requests/), [FileResponse](https://starlette.dev/responses/#fileresponse)의 공식 API를 사용한다. 라이브러리 추가 없이 기존 잠금 의존성을 유지했다.
