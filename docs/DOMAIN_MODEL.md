## 의장 선출·겸임과 임기

의장은 별개의 학생 집단에서 임명하는 사람이 아니라 **이미 학회장으로 정해진 사람 중 학회장들이 투표로 뽑은 대표**다(DM-C05). 의장과 그 사람이 맡은 자기 학과 학회장의 공식 임기는 같다. 역할별 범위·자격을 판정한다는 Q9를 근거로 두 직책의 임기가 서로 다르다고 가정하지 않는다.

예를 들어 스마트소프트웨어학과 학회장 A가 의장으로 선출되면, A는 같은 계정에서 스마트소프트웨어학과 학회장과 학과협의회 의장을 함께 맡는다. 학회장 범위는 자기 학과, 의장 범위는 협의회 전체다. 다른 학과 학회장에게 의장 권한이 자동 생기지는 않는다.

학회장들의 선출과 선생님의 포털 역할 부여는 서로 다른 사실이다. 선생님은 선출된 의장에게 기존 합의대로 서비스 권한을 부여한다. 공식 임기를 같게 표현하되 선출·역할 부여 전 시점의 업무 권한을 소급 허용하지 않는다(Q26). 투표 기능을 포털에 구현할지와 선거의 상세 규칙은 이번 설명만으로 확정하지 않는다.

| 상황 | 기대 결과 | 상태 |
|---|---|---|
| 학회장 A가 학회장들의 투표로 의장에 선출 | 같은 사람에게 학과 학회장·협의회 의장 범위 연결, 공식 임기 동일 | C: DM-C05 |
| 학회장이지만 의장으로 선출되지 않은 B | 자기 학과 학회장 범위만 보유, 의장 권한 자동 부여 금지 | C |
| 공유하는 공식 임기 종료 | 학회장·의장 역할 모두 종료, 자료·이력 보존 | C |
| 임기 중 자기 학과 학회장 자격 종료 | 의장 자격도 종료, 자료·이력 보존 | C: DM-C02 |
| 학년도 자료 분류 변경, 자격·임기는 유효 | 분류 변경만으로 역할 종료 금지 | C: Q48 |
| 의장만 사임·교체하거나 학회장 자격을 다시 얻는 중도 상황 | 재선출·직무 대행·등록의 상세 절차는 DM-O04에서 확인. 선생님의 단독 임명이나 자동 복귀로 확정하지 않음 | O |

이전 모델의 서로 다른 종료일·남은 의장 임기 사례는 DM-C05로 대체했다. 종료 사유·시각과 전제 자격을 연결하는 방식은 P다. 구현 전 실제 임기 경계와 중도 선출 절차를 정한다.

## 개별 지출과 전체 정산

실제로 120,000원을 썼지만 배정 잔액이 100,000원이라면 지출 사실 120,000원을 남기고 초과 20,000원을 구분한다. 등록 거부·반려·미검토로 사용 사실을 지우거나 예산을 자동으로 늘리지 않는다(Q21~22, Q50~51).

지출 확인 결과, 실제 사용액, 초과분 처리 결과, 정산 확정 여부는 서로 다른 사실이다. DM-C04에 따라 기본 집계는 다음과 같다.

- 실제 집행액 = 해당 범위에서 실제 발생한 지출의 현재 반영 금액 합계. 검토 대기·확인 완료·반려를 모두 포함한다.
- 연간 실제 집행 기준 잔액 = 해당 단체 연간 예산 − 해당 연간 범위의 실제 집행액.
- 행사 실제 집행 기준 잔액 = 해당 행사 배정액 − 해당 행사 실제 집행액.
- 초과액 = 실제 집행액이 해당 예산 한도를 넘은 부분. 잔액이 음수면 그 절댓값, 아니면 0이다.
- 검토 대기액·확인 완료액·반려액은 현재 개별 검토 상태별 집계다. 실제 집행액에 포함된 금액이므로 잔액에서 또 차감하지 않는다.

예산 100,000원에 실제 지출 120,000원이 검토 대기라면 실제 집행 기준 잔액 -20,000원·초과액 20,000원·검토 대기액 120,000원이다. 확인 완료 또는 반려로 바뀌면 해당 상태별 집계만 옮기며 실제 집행액·잔액·초과액은 유지한다. 반려를 환불로 취급하지 않는다.

행사 배정과 실제 지출을 연간 지출에 이중 합산하지 않는다. 같은 지출의 수정·재제출·검토 회차는 이력으로 보존하되 현재 반영 금액을 한 번만 집계한다. 연간 초과액과 행사 초과액은 범위가 겹치므로 별도 항목으로 표시하고 단순 합산하지 않는다. 환불·정정으로 실제 반영 금액이 달라지는 시점과 예외 결과·후속 절차는 DM-O02에서 추가 결정한다.

일반 지출 본인 확인 허용은 확인 업무 권한과 담당 범위가 있는 사람에게 적용한다. 등록자나 집행 담당자라는 사실만으로 확인 권한이 생기지 않는다. 초과분 예외 확인은 해당 단체 최고 책임자가 맡으며, 그 책임자 본인이 실제 집행한 건은 담당 선생님이 맡는다(DM-C03). 등록을 다른 담당자가 대신해도 실제 집행자 기준은 바뀌지 않는다. 확인자의 담당 범위·유효 자격을 확인하고 예산은 자동 증액하지 않는다.

## 기존 문서·코드와의 정합성

기존 F/M/AUTH/T ID를 유지하며 이번 개념과 직접 충돌하는 조직·권한·회계·인수인계 내용을 함께 갱신한다. 세부 화면·물리 스키마·예외 절차까지 모두 확정한 명세 v1.0은 아니다.

현재 apps/web와 apps/api에는 [조직·권한 로컬 프로토타입](PROTOTYPE.md)이 있다. 자료·회계·인수인계·AI 업무 코드는 아직 없다. 기존 논리 모델의 소속과 운영기 강제 연결, 일괄 자기승인 금지, 초과 발생 기록 거부, 서로 다른 운영기만 허용하는 인수인계는 최신 합의에 맞춰 논리 명세를 보완했으며 각 기능의 실제 구현은 위 범위와 구분한다. 기존 Git 정책 코드의 검증과 도메인 업무 검증을 혼동하지 않는다.

## S20 역할 종류와 부여 기록 (2026-11-13)

최신 조직 구성은 부서별 부장·차장과 각 동아리 회장·부회장·총무를 구분한다(C). 역할 종류는 단체와 적용할 소속 수준의 정의이며, 역할 부여는 사람·범위·공식 임기를 가진 별도 기록이다. 종류를 추가했다고 개인에게 업무 권한이 생기는 것은 아니다. 선생님은 종류 관리와 모든 범위 역할 부여를 할 수 있다(C).

구현 P: 종류 삭제는 해당 부여를 회수하되 역사와 외래키를 보존한다. 학회장 자격을 없애면 연결된 의장도 종료한다. 종류 재등록은 이전 역할을 복구하지 않는다. 최고 책임자의 명시적 배정은 같은 단체의 여러 부서 소속을 추가할 수 있으나 하위 담당자의 범위를 넓히지 않는다. 직책 이름·연락처 열람·회계 권한·재위임을 동일시하지 않는다.

## S22 겹치는 공유 대상과 별도 관리 권한

학과협의회 간부진은 학회장·부학회장, 학과 담당자 그룹은 해당 학과의 학회장·부학회장·반대표다(C). 같은 학회장·부학회장은 두 공유 대상에 함께 속하되 협의회 전체 계정·역할·개인정보 관리 권한까지 얻지는 않는다. 반대표의 역할 단위는 학과/학년/반이며 자기 학과 공유 대상으로 연결된다.

공유 대상은 현재 유효한 역할로 계산하며 계정 소속이나 임기 지난 기록만으로 만들지 않는다(P). 학회장은 자기 학과의 학년·반과 반대표 등록·역할을 관리한다(C). 의장은 학회장에 연결된 별도 자격이지만 화면에서는 해당 학회장 카드에 표시한다(C). 해제·종료 의존과 정식 선출 사실 확인은 유지한다.
