## 준비와 실행

저장소 루트의 Windows PowerShell에서:

```powershell
python -m venv apps/api/.venv
.\apps\api\.venv\Scripts\python.exe -m pip install -r apps/api/requirements-lock.txt
npm.cmd ci --prefix apps/web
```

터미널 1:

```powershell
.\apps\api\.venv\Scripts\python.exe -m uvicorn yeonieum.main:create_app --factory --app-dir apps/api/src --host 127.0.0.1 --port 8000
```

터미널 2:

```powershell
npm.cmd run dev --prefix apps/web
```

[로컬 화면](http://127.0.0.1:5173), [API 문서](http://127.0.0.1:8000/docs). macOS/Linux에서는 Python 경로를 `apps/api/.venv/bin/python`으로 바꾸고 `npm`을 사용한다. Node 24 및 Python 3.11에서 검증한다. 패키지는 앱별 잠금 파일로 고정한다.

최초 실행은 `local-data/prototype.sqlite3`에 가상 단체·학과·학년·반·계정·역할을 만든다. 재시작은 기존 기록을 보존하며 자동 초기화하지 않는다. 별도 가상 DB가 필요하면 실행 전 `YEONIEUM_DB_PATH`로 새 경로를 지정한다. 실제 학교 개인정보·자료를 입력하지 않는다. 기본 SQLite 파일과 브라우저 검사 산출물은 Git 제외다.

## 가상 계정

모든 시드 계정의 시연 비밀번호는 `Yeonieum-demo-2026!`다. 새로 등록한 계정은 로그인 화면의 ‘등록한 계정 직접 입력’을 사용한다.

| 가상 식별자 | 역할 |
|---|---|
| staff-demo | 담당 선생님 |
| student-chair | 의장 + 스마트소프트웨어학과 학회장 |
| student-head | 기계공학과 학회장 |
| student-vice | 부학회장, 재위임 불가 |
| student-rep | 스마트소프트웨어학과 1학년 A반 대표 |
| student-new | 역할 미부여 담당자 |
| student-other | 총학생회 학생회장 |

학과명·학과 조직 구성은 시연용이며 전체 실제 학교 조직도를 입력한 것이 아니다. 공식 임기는 시드 생성 연도 1월 1일 UTC부터 다음 해 1월 1일 UTC 미만이다. 실제 운영 임기와 학년도 경계는 DM-O05 미정이다. 화면의 임기 시작은 한국 시간 00시, 종료일은 해당 날짜 전체를 포함한다. 기본값은 한국 시간 기준 해당 연도 1월 1일~12월 31일이다. 의장은 전제 학회장 기간을 그대로 사용하며 기존 기록의 시간값은 변경하지 않는다.

## 시연 순서

1. 선생님으로 로그인해 담당자 등록을 연다. 가상 이름·이메일·학번·전화번호·소속·비밀번호를 입력한다. 소속은 여러 개 선택할 수 있다. 등록 후 로컬 초대 수신함의 링크로 인증을 완료해야 로그인할 수 있으며 등록만으로 업무 역할이 생기지 않는다.
2. 역할 부여에서 학회장을 선택한다. 기존 학회장 임기와 겹치지 않는 차기 임기로 등록하면 시작 전 권한이 활성화되지 않는다. 현재 직책 교체 시에는 선생님이 기존 역할을 사유와 함께 회수한 뒤 새 역할을 부여한다.
3. 의장 계정으로 협의회 전체와 자기 학과의 두 범위를 확인한다. 자기 학과 2학년 A반의 신규 담당자에게 반대표를 부여한다.
4. 학회장 계정은 자기 학과만 조회·지정한다. 부학회장·반대표 계정은 추가 역할 부여와 감사 조회를 할 수 없고 일반 담당자의 전체 연락처를 조회할 수 없다.
5. 선생님이 의장의 전제 학회장 자격을 회수한다. 기존 의장 세션으로 다음 요청을 하면 의장 권한도 종료된다. 자료·계정·감사 기록은 삭제하지 않는다.
6. 선생님은 전체, 최고 책임자는 자기 단체의 활동 이력을 확인한다. 변경 사유와 역할 부여·회수·전제 자격 종료가 각각 남는다.

의장 선출은 실제 학회장들의 투표 사실을 선생님이 확인 메모로 기록하는 방식이다. 온라인 투표나 선생님의 단독 선출 기능을 구현한 것이 아니다. 중도 선출·대행에 대한 실제 학교 규칙은 별도 확인한다.

## 검사

```powershell
.\apps\api\.venv\Scripts\python.exe -m ruff check apps/api
.\apps\api\.venv\Scripts\python.exe -m ruff format --check apps/api
.\apps\api\.venv\Scripts\python.exe -m pytest apps/api -q
npm.cmd run format:check --prefix apps/web
npm.cmd run build --prefix apps/web
npm.cmd run test:e2e --prefix apps/web
```

브라우저 테스트는 기존 데모 DB와 별개의 고유 SQLite 파일·파일 폴더를 사용한다. E2E 기본 포트는 API 8010·웹 5180으로 일반 시연의 8000·5173과 분리했으므로 시연 서버를 종료할 필요가 없다. 로컬 Chrome, CI에서는 Playwright Chromium을 사용한다. Linux CI는 `npx playwright install --with-deps chromium`을 실행한다. 필요하면 `YEONIEUM_E2E_API_PORT`, `YEONIEUM_E2E_WEB_PORT`로 테스트 포트만 바꾼다.

과거 조직·권한 검사 수치는 해당 시점 기록이다. 현재는 일반 자료실의 T-42~48을 추가 검증한다. T-04~16 전체 통과, Cognito·PostgreSQL·AWS 검증 또는 학교 운영 승인으로 표현하지 않는다. 실제 검사 수와 결과는 해당 변경에서 다시 확인한다.

## 일반 자료실 사용법 (2026-11-16)

1. 기존 API 서버가 켜져 있다면 Ctrl+C 후 같은 명령으로 재시작한다. 기존 DB는 그대로 유지한다. 웹의 ‘자료실’ 메뉴를 연다.
2. 선생님은 ‘선생님의 일반 자료 관리 범위 설정’을 펼치고 작업할 단체의 ‘자료 권한 설정’을 누른다. 현재 담당 역할이 있는 학생은 자기 범위를 사용한다.
3. ‘자료 등록’에서 파일을 선택하고 보관 위치와 열람 대상을 확인한다. 일반 자료는 파일당 200 MiB까지이며 텍스트는 UTF-8이다.
4. 제목·설명·파일명 또는 분류로 검색하고 자료를 누르면 상세·버전·다운로드를 확인한다. ‘새 버전 등록’은 이전 파일을 보존한다. 과거 파일의 ‘이 버전 복원’은 새 버전을 만든다.
5. ‘분류·공유 수정’에서 간부진/학과 대상을 조정할 수 있다. 휴지통 이동은 별도 확인 후 실행하며 자료함을 휴지통으로 바꾸고 검색하면 관리 가능한 삭제 자료를 복원할 수 있다.
6. 일반 자료 파일은 `local-data/prototype-files`, 민감 증빙 파일은 `local-data/prototype-evidence`, 메타데이터는 기존 SQLite에 보관한다. DB만 복사하면 파일 백업이 되지 않는다. [검증된 별도 폴더 백업·복원](design/DOCUMENT_LIBRARY.md#백업복원)을 따른다.
7. 관리자 권한으로 단체 자료함을 열고 파일을 폴더 카드나 상단 경로의 상위 폴더·‘단체 공유’에 끌어 놓는다. 파일 상세의 ‘폴더로 이동’에서도 같은 자료함 안의 위치를 고를 수 있다.
8. 자료실 왼쪽에서 연도를 고르고 해당 연도의 제목·파일명·폴더를 검색한다. 파일을 클릭하면 읽기 창이 열리며 ‘파일 정보’로 분류·버전을 확인한다. 역할이 없는 인증 계정은 활성 소속의 개인 보관함에 자료를 등록할 수 있다.
9. ‘자료 등록’에서 파일 여러 개를 선택하거나 놓는다. 일반 자료는 파일당 최대 200 MiB다. 한글 인쇄 미리보기의 로컬 변환기는 [자료실 변환기 설정](design/DOCUMENT_LIBRARY.md#한글-인쇄-미리보기와-여러-파일-등록-2026-11-22)을 따른다.

## 예산·인수인계 로컬 시연

1. API를 재시작한 뒤 기존 웹 화면을 새로고침한다. 선생님으로 ‘예산 · 정산’에 들어가 단체별 **회계 내역 열람**과 필요한 업무 권한을 현재 담당자에게 명시적으로 부여한다. 선생님 본인이 입력·검토·증빙을 할 경우에도 별도 체크한다.
2. 편성 담당자는 연간 예산과 행사 배정을 등록한다. 지출 기록 담당자는 실제 집행 담당자·집행일·금액·용도를 저장하고 증빙 권한자는 가상 영수증 파일을 첨부한다. 검토 담당자가 개별 확인 또는 반려를 기록한다.
3. 행사 또는 연간 예산 초과 지출은 최고 책임자가 별도로 확인한다. 최고 책임자 본인 집행 건은 선생님이 확인한다. 선생님은 미검토·초과분 미처리·증빙 없는 지출이 없을 때 전체 정산을 확정한다.
4. ‘인수인계’에서 인계자·후임을 지정하고 업무 메모·자료 ID·확정 정산을 연결한다. 후임 담당자가 필수 항목을 직접 확인한 뒤 완료한다. 역할 부여·회수는 ‘조직 · 권한’에서 별도로 수행한다.

이 흐름은 가상 데이터 전용이다. 확정 후 정정·실제 학교 회계 규정·운영 인증·AWS 복구는 [후속 범위](design/LOCAL_FINANCE_HANDOVER.md)다.

민감 증빙·실데이터·실제 학교 인증·외부 메일·AWS 배포·AI는 이번 자료실에 포함하지 않는다. 파일 형식의 기본 검사와 악성코드 검사를 구분한다. 커밋·푸시는 별도 사용자 지시가 있을 때 수행한다.

검증: Python 3.11.9·Node 24에서 API 99개(자료실 21개·예산/인수인계 3개 포함), 브라우저 16개(자료실 4개·예산/인수인계 1개 포함), Git 정책 12개가 통과했다. Ruff·Prettier·타입·웹 빌드·공통 pre-commit도 확인했다. 이번 변경은 로컬에만 있어 새 원격 CI 결과는 없다. 기존 FastAPI TestClient의 httpx 사용 중단 예정 경고 1개는 남아 있다.

## 관리자 화면 보완 시연 (2026-11-13)

- 선생님 로그인 → 조직·권한 → 단체 관리: 기본 5개 및 신설 단체를 추가·삭제한다. 삭제 시 ‘단체를 삭제하시겠습니까?’ 창에서 ‘삭제하겠습니다’를 정확히 입력한다. 삭제된 이름을 다시 추가하면 기존 ID와 하위 소속을 복원한다. 이전 담당자의 권한과 제거된 계정은 자동 복구되지 않는다.
- 가상 담당자 등록: 소속은 운영 단체만 표시하며 전화번호는 숫자를 입력하면 자동 하이픈이 붙는다. 학과/반은 역할 부여 시 담당 범위로 지정한다.
- 담당자 목록의 제거: ‘담당자를 제거하시겠습니까?’ 창에 ‘제거하겠습니다’를 입력한다. 해당 학생의 로그인과 모든 업무 역할이 종료된다. 역할·감사 이력과 단체의 과거 기록은 보존한다.
- 역할과 임기는 계정 목록과 별개인 권한/기간 기록이다. 계정을 유지하면서 특정 역할만 회수할 수 있다. 역할 부여 성공·중복·필수 입력 오류는 버튼 위에 표시한다.

API 75개 및 브라우저 11개 테스트로 관리자 제한·정확한 확인 문구·세션 종료·운영 제외·재시작 보존·등록/역할 부여 오류 표시를 검증한다. 누적 변경의 커밋·푸시는 사용자 지시에 따라 기능 브랜치로 수행한다. 자동 푸시는 하지 않는다.

## 등록·초대·계정 복구 시연 (S19)

1. 선생님으로 가상 담당자를 등록한다. 학번은 숫자 8자리, 비밀번호는 8자 이상 숫자·특수문자를 포함한다. 소속 체크박스는 여러 개 선택할 수 있다.
2. 로컬 초대 수신함의 해당 담당자 ‘초대 확인 열기’를 누른다. 인증 완료 버튼을 눌러 1회 확인한다. 외부 이메일은 보내지 않으며 실제 이메일 소유를 증명하지 않는다.
3. 등록한 학번·비밀번호로 직접 로그인한다. 초대 인증 전에는 로그인할 수 없다. 업무 역할은 별도 부여한다.
4. 선생님이 해당 계정을 제거하고 같은 학번·이메일로 다시 등록하면 같은 계정이 복구된다. 새 초대 인증과 역할 부여가 필요하다. 예전 링크와 역할은 되살아나지 않는다.
5. 링크 만료 또는 잘못된 이메일 테스트 후에는 올바른 가상 계정을 사용하고 필요 시 1분 뒤 초대 재발급을 시연한다. 실제 메일 서비스·외부 HTTPS 주소는 미구현이다.

API 75개·브라우저 11개 테스트로 등록 조건, 초대 만료/재사용/무효화, 복구, 다중 소속 경계를 검증한다. [세부 계약과 운영 전 미결정](design/INVITATIONS.md).

## 하위 조직·역할 종류 관리 시연 (S20)

1. 선생님 → 조직·권한 → 하위 조직·역할 종류 관리에서 단체를 선택한다.
2. 상위 조직·하위 조직명을 입력해 부서/동아리 또는 학과→학년→반을 등록한다.
3. 역할 종류 추가에서 이름과 적용할 범위 종류를 선택한다. 기본 부장·차장, 동아리 회장·부회장·총무도 관리할 수 있다.
4. 역할 부여에서 단체와 담당 범위를 먼저 고른다. 그 범위의 역할과 담당자·임기를 선택해 부여한다. 같은 단체의 여러 부서 겸임도 가능하다.
5. 역할 종류 삭제는 해당 역할 전체의 현재·예약 부여를 회수한다. 담당자 한 명만 종료하려면 기존 ‘역할 회수’를 사용한다. 같은 이름 재추가는 정의만 복원한다.

실제 부서·동아리 이름은 사용자가 등록하며 새 직책명만으로 역할 관리·회계 권한을 얻지 않는다. [역할 종류 구현 계약](design/ROLE_CATALOG.md).

S21 시연: 역할 부여의 임기 기본값은 해당 연도 01-01과 12-31이다. 종료일의 업무는 당일 23:59:59까지 유효하고 한국 시간 다음 날 00시에 종료된다. 역할을 회수하거나 역할 종류 삭제로 회수되면 ‘역할과 임기’ 목록에서 즉시 숨긴다. 활동 이력과 원래 부여 기록은 남는다.

## 학과협의회·학과 담당자 시연 (S22)

1. 학회장 계정 → 조직·권한 → 학과 하위 조직 관리에서 학과협의회를 선택한다. 자기 학과를 상위 조직으로 학년을 등록하고, 그 학년 아래 A반/B반 등을 만든다.
2. 가상 담당자 등록에서 만든 반을 소속으로 선택한다. 로컬 초대 인증 후 단체→범위→반대표 역할→담당자를 골라 부여한다. ‘1학년 A반 반대표’처럼 표시된다.
3. ‘학과협의회·학과별 그룹’에서 간부진과 자기 학과 공유 대상을 확인한다. 간부진은 학회장·부학회장이고, 각 학과에는 이들과 반대표가 함께 묶인다. 이 화면은 공유 대상 준비이며 실제 자료실은 아직 없다.
4. 선생님은 학회장 카드의 ‘의장 지정’에서 선출 확인을 입력한다. 의장 자격은 같은 카드에 표시되며 의장만 해제해도 학회장 역할은 유지한다.

실제 학과·학년·반 목록은 학교 확인 후 등록한다. 예시 명칭을 실제 학교 전체 조직도로 간주하지 않는다. [그룹과 권한 모델](design/ACADEMIC_SCOPES.md).

완료 판단은 [조직·권한 프로토타입과 전체 포털의 단계별 완료 기준](PROTOTYPE_COMPLETION.md)을 따른다.

S23 시연: 하위 조직 관리에서 단체를 고르면 ‘등록된 하위 조직’ 목록과 삭제 버튼이 표시된다. 상위 조직을 고르면 바로 아래 조직만 표시한다. 삭제 창의 강조된 ‘정말로 삭제하시겠습니까?’와 유의사항을 확인한다. ‘유의사항을 확인했으며, 삭제하겠습니다.’를 체크한 뒤 삭제 버튼을 누른다. 체크만으로 삭제하지 않으며 다시 열면 체크가 초기화된다. 학년 삭제 시 아래 반도 함께 삭제되고 현재·예약 역할은 회수되며 계정·이력은 보존된다. 같은 상위 조직에 같은 이름/종류로 등록하면 기존 하위 구조가 복원된다. 이전에 따로 삭제했던 반은 상위 복원으로 되살아나지 않는다. 이전 역할은 새로 부여해야 한다.

S25 시연: 조직·권한의 담당자 목록은 현재 유효한 자치단체장부터 표시한다. 더보기로 나머지를 펼치고 접기로 돌아간다. 이름 또는 단체명으로 검색하면 접힌 인원도 포함하고 여러 소속의 같은 사람은 한 행에만 나타난다. 검색을 비우면 기본 목록으로 돌아간다. 신규/복구 등록 직후에는 등록 결과 확인을 위해 펼친다. 역할과 임기는 단체 버튼을 누르면 해당 담당자의 역할만 표시하며 성공적으로 역할을 부여하면 해당 단체를 자동 선택한다. 기존 서버의 조회·연락처 제한은 유지한다.

S26 사용법: 상위 조직에 학과를 고른 뒤 1학년·3학년을 등록한다. 다음에는 상위 조직에 해당 학년을 골라 A반·SAP반을 등록한다. 새 반은 역할 부여의 담당 범위와 반대표 역할에 자동 연결되며 대상 담당자·임기를 확인해 부여한다. 기존 1A·3SAP처럼 학년으로 잘못 등록한 빈 항목은 목록의 ‘반으로 변경’에서 학년과 반 이름을 확인해 변경한다. 학년이 없으면 대화창의 ‘먼저 학년 등록·복원하기’로 준비한 뒤 다시 변경한다. 삭제된 학년 복원은 같은 삭제 묶음의 반도 복원하므로 이미 A반 등이 있으면 해당 반을 사용하며 기존 반과 자동 합치지 않는다. 하위 조직/역할 이력이 있는 항목은 보존하고 올바른 반을 따로 등록한다.

## 참고 이미지 기반 워크스페이스 UI

상단 헤더·그룹형 왼쪽 메뉴·업무 진입 카드와 현황 패널로 배치를 보완했다. 리넨 팔레트·학교 로고·Pretendard와 기존 조직/자료실/회계/인수인계 정책을 유지한다. 데스크톱은 메뉴를 접고 펼칠 수 있으며 모바일은 3열 업무 메뉴로 이동한다. 화면 구조·구현 위치·검증 범위는 [워크스페이스 UI](design/WORKSPACE_UI.md)를 따른다. 자료실의 학년도/상시 자료 구성과 공유 권한에 대한 인터뷰는 별도 진행 중이다.

캘린더(2026-11-19 갱신): 대시보드 날짜 또는 ‘일정 추가’에서 오른쪽 패널을 열어 일정·반복·참여자·링크·자료 참조·포털 리마인더를 저장한다. 월간/주간/일간·작은 달력·오늘/날짜 이동, 검색, 우클릭 복사, Ctrl/Cmd+K 명령어, 확대 보기와 시간축 드래그를 제공한다. 한국 시간/UTC를 선택하며 종일은 한국 시간 기준이다. 반복 수정·삭제는 전체 시리즈에 적용한다. 외부 동기화·메일/푸시 알림은 없으며 실제 권한·보존·미구현 범위는 [캘린더 계약](design/CALENDAR.md)을 따른다.

최신 검증(2026-11-19): 전체 API **129개**(캘린더 30개 포함), 브라우저 **21개**(캘린더 4개 포함), Ruff·Prettier·TypeScript·웹 빌드·공통 pre-commit 통과. UTC 반복 종료일, 읽기 전용 상위 범위의 참여자 선택 차단, 회수된 참여자 숨김과 과거 연결 보존을 보완했다. 기존 FastAPI TestClient 경고 1개는 남아 있다. 별도 가상 DB·8010/5180에서 검사했으며 실제 AWS·학교 인증·원격 CI 검증은 아니다. 기존 DB·파일과 미커밋 변경을 보존하고 커밋·푸시는 수행하지 않았다.

추가 화면 검증(2026-11-19): 사용자 이미지에 따라 시간 한 줄·기간·종일 토글과 둥근 날짜/시간 선택창을 적용했다. 캘린더 브라우저 **5개**, Prettier·TypeScript·웹 빌드·공통 pre-commit 통과. 15분 간격/직접 입력, 월 이동·키보드·닫기, 종일 전환과 다일 일정 저장, 320/390px 선택창을 확인했다. 앞 문단의 전체 API/브라우저 검사는 이 화면 변경 전 결과이며 이번 변경에서 서버 코드를 수정하거나 전체 API 검사를 다시 실행하지 않았다.
