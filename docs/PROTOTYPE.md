# 조직·권한 프로토타입 실행과 시연

2026-11-13. 첫 수직 구현은 로컬 가상 데이터의 로그인·소속·역할·감사다. 자료실·예산·인수인계·AI·AWS는 미구현이며 [상세 설계](design/PROTOTYPE_DESIGN.md)와 기존 F/M/T 요구를 후속 구현 기준으로 사용한다.

## 준비와 실행

저장소 루트의 Windows PowerShell에서:

```powershell
python -m venv apps/api/.venv
.\apps\api\.venv\Scripts\python.exe -m pip install -r apps/api/requirements-lock.txt
npm.cmd ci --prefix apps/web
```

터미널 1:

```powershell
.\apps\api\.venv\Scripts\python.exe -m uvicorn yeonieum.main:create_app --factory --app-dir apps/api/src --host 127.0.0.1 --port 8000
```

터미널 2:

```powershell
npm.cmd run dev --prefix apps/web
```

[로컬 화면](http://127.0.0.1:5173), [API 문서](http://127.0.0.1:8000/docs). macOS/Linux에서는 Python 경로를 `apps/api/.venv/bin/python`으로 바꾸고 `npm`을 사용한다. Node 24 및 Python 3.11에서 검증한다. 패키지는 앱별 잠금 파일로 고정한다.

최초 실행은 `local-data/prototype.sqlite3`에 가상 단체·학과·학년·반·계정·역할을 만든다. 재시작은 기존 기록을 보존하며 자동 초기화하지 않는다. 별도 가상 DB가 필요하면 실행 전 `YEONIEUM_DB_PATH`로 새 경로를 지정한다. 실제 학교 개인정보·자료를 입력하지 않는다. 기본 SQLite 파일과 브라우저 검사 산출물은 Git 제외다.

## 가상 계정

모든 시드 계정의 시연 비밀번호는 `Yeonieum-demo-2026!`다. 새로 등록한 계정은 로그인 화면의 ‘등록한 계정 직접 입력’을 사용한다.

| 가상 식별자 | 역할 |
|---|---|
| staff-demo | 담당 선생님 |
| student-chair | 의장 + 스마트소프트웨어학과 학회장 |
| student-head | 기계공학과 학회장 |
| student-vice | 부학회장, 재위임 불가 |
| student-rep | 스마트소프트웨어학과 1학년 A반 대표 |
| student-new | 역할 미부여 담당자 |
| student-other | 총학생회 학생회장 |

학과명·학과 조직 구성은 시연용이며 전체 실제 학교 조직도를 입력한 것이 아니다. 공식 임기는 시드 생성 연도 1월 1일 UTC부터 다음 해 1월 1일 UTC 미만이다. 실제 운영 임기와 학년도 경계는 DM-O05 미정이다. 화면의 임기 시작은 한국 시간 00시, 종료일은 해당 날짜 전체를 포함한다. 기본값은 한국 시간 기준 해당 연도 1월 1일~12월 31일이다. 의장은 전제 학회장 기간을 그대로 사용하며 기존 기록의 시간값은 변경하지 않는다.

## 시연 순서

1. 선생님으로 로그인해 담당자 등록을 연다. 가상 이름·이메일·학번·전화번호·소속·비밀번호를 입력한다. 소속은 여러 개 선택할 수 있다. 등록 후 로컬 초대 수신함의 링크로 인증을 완료해야 로그인할 수 있으며 등록만으로 업무 역할이 생기지 않는다.
2. 역할 부여에서 학회장을 선택한다. 기존 학회장 임기와 겹치지 않는 차기 임기로 등록하면 시작 전 권한이 활성화되지 않는다. 현재 직책 교체 시에는 선생님이 기존 역할을 사유와 함께 회수한 뒤 새 역할을 부여한다.
3. 의장 계정으로 협의회 전체와 자기 학과의 두 범위를 확인한다. 자기 학과 2학년 A반의 신규 담당자에게 반대표를 부여한다.
4. 학회장 계정은 자기 학과만 조회·지정한다. 부학회장·반대표 계정은 추가 역할 부여와 감사 조회를 할 수 없고 일반 담당자의 전체 연락처를 조회할 수 없다.
5. 선생님이 의장의 전제 학회장 자격을 회수한다. 기존 의장 세션으로 다음 요청을 하면 의장 권한도 종료된다. 자료·계정·감사 기록은 삭제하지 않는다.
6. 선생님은 전체, 최고 책임자는 자기 단체의 활동 이력을 확인한다. 변경 사유와 역할 부여·회수·전제 자격 종료가 각각 남는다.

의장 선출은 실제 학회장들의 투표 사실을 선생님이 확인 메모로 기록하는 방식이다. 온라인 투표나 선생님의 단독 선출 기능을 구현한 것이 아니다. 중도 선출·대행에 대한 실제 학교 규칙은 별도 확인한다.

## 검사

```powershell
.\apps\api\.venv\Scripts\python.exe -m ruff check apps/api
.\apps\api\.venv\Scripts\python.exe -m ruff format --check apps/api
.\apps\api\.venv\Scripts\python.exe -m pytest apps/api -q
npm.cmd run format:check --prefix apps/web
npm.cmd run build --prefix apps/web
npm.cmd run test:e2e --prefix apps/web
```

브라우저 테스트는 기존 데모 DB와 별개의 고유 SQLite 파일을 만들고 테스트용 서버를 시작·종료한다. 로컬 Chrome, CI에서는 Playwright Chromium을 사용한다. 테스트 전에 8000·5173 포트의 일반 시연 서버를 종료한다. Linux CI는 `npx playwright install --with-deps chromium`을 실행한다.

13개 API 테스트는 T-01~03·17~19 중 구현 범위만 확인한다. T-04~16 전체 통과, Cognito·PostgreSQL·AWS 검증 또는 학교 운영 승인으로 표현하지 않는다. 실제 테스트 결과와 커밋은 후속 변경 시 다시 확인한다.

## 관리자 화면 보완 시연 (2026-11-13)

- 선생님 로그인 → 조직·권한 → 단체 관리: 기본 5개 및 신설 단체를 추가·삭제한다. 삭제 시 ‘단체를 삭제하시겠습니까?’ 창에서 ‘삭제하겠습니다’를 정확히 입력한다. 삭제된 이름을 다시 추가하면 기존 ID와 하위 소속을 복원한다. 이전 담당자의 권한과 제거된 계정은 자동 복구되지 않는다.
- 가상 담당자 등록: 소속은 운영 단체만 표시하며 전화번호는 숫자를 입력하면 자동 하이픈이 붙는다. 학과/반은 역할 부여 시 담당 범위로 지정한다.
- 담당자 목록의 제거: ‘담당자를 제거하시겠습니까?’ 창에 ‘제거하겠습니다’를 입력한다. 해당 학생의 로그인과 모든 업무 역할이 종료된다. 역할·감사 이력과 단체의 과거 기록은 보존한다.
- 역할과 임기는 계정 목록과 별개인 권한/기간 기록이다. 계정을 유지하면서 특정 역할만 회수할 수 있다. 역할 부여 성공·중복·필수 입력 오류는 버튼 위에 표시한다.

API 51개 및 브라우저 8개 테스트로 관리자 제한·정확한 확인 문구·세션 종료·운영 제외·재시작 보존·등록/역할 부여 오류 표시를 검증한다. 누적 변경의 커밋·푸시는 사용자 지시에 따라 기능 브랜치로 수행한다. 자동 푸시는 하지 않는다.

## 등록·초대·계정 복구 시연 (S19)

1. 선생님으로 가상 담당자를 등록한다. 학번은 숫자 8자리, 비밀번호는 8자 이상 숫자·특수문자를 포함한다. 소속 체크박스는 여러 개 선택할 수 있다.
2. 로컬 초대 수신함의 해당 담당자 ‘초대 확인 열기’를 누른다. 인증 완료 버튼을 눌러 1회 확인한다. 외부 이메일은 보내지 않으며 실제 이메일 소유를 증명하지 않는다.
3. 등록한 학번·비밀번호로 직접 로그인한다. 초대 인증 전에는 로그인할 수 없다. 업무 역할은 별도 부여한다.
4. 선생님이 해당 계정을 제거하고 같은 학번·이메일로 다시 등록하면 같은 계정이 복구된다. 새 초대 인증과 역할 부여가 필요하다. 예전 링크와 역할은 되살아나지 않는다.
5. 링크 만료 또는 잘못된 이메일 테스트 후에는 올바른 가상 계정을 사용하고 필요 시 1분 뒤 초대 재발급을 시연한다. 실제 메일 서비스·외부 HTTPS 주소는 미구현이다.

API 51개·브라우저 8개 테스트로 등록 조건, 초대 만료/재사용/무효화, 복구, 다중 소속 경계를 검증한다. [세부 계약과 운영 전 미결정](design/INVITATIONS.md).

## 하위 조직·역할 종류 관리 시연 (S20)

1. 선생님 → 조직·권한 → 하위 조직·역할 종류 관리에서 단체를 선택한다.
2. 상위 조직·하위 조직명을 입력해 부서/동아리 또는 학과→학년→반을 등록한다.
3. 역할 종류 추가에서 이름과 적용할 범위 종류를 선택한다. 기본 부장·차장, 동아리 회장·부회장·총무도 관리할 수 있다.
4. 역할 부여에서 단체와 담당 범위를 먼저 고른다. 그 범위의 역할과 담당자·임기를 선택해 부여한다. 같은 단체의 여러 부서 겸임도 가능하다.
5. 역할 종류 삭제는 해당 역할 전체의 현재·예약 부여를 회수한다. 담당자 한 명만 종료하려면 기존 ‘역할 회수’를 사용한다. 같은 이름 재추가는 정의만 복원한다.

실제 부서·동아리 이름은 사용자가 등록하며 새 직책명만으로 역할 관리·회계 권한을 얻지 않는다. [역할 종류 구현 계약](design/ROLE_CATALOG.md).

S21 시연: 역할 부여의 임기 기본값은 해당 연도 01-01과 12-31이다. 종료일의 업무는 당일 23:59:59까지 유효하고 한국 시간 다음 날 00시에 종료된다. 역할을 회수하거나 역할 종류 삭제로 회수되면 ‘역할과 임기’ 목록에서 즉시 숨긴다. 활동 이력과 원래 부여 기록은 남는다.

## 학과협의회·학과 담당자 시연 (S22)

1. 학회장 계정 → 조직·권한 → 학과 하위 조직 관리에서 학과협의회를 선택한다. 자기 학과를 상위 조직으로 학년을 등록하고, 그 학년 아래 A반/B반 등을 만든다.
2. 가상 담당자 등록에서 만든 반을 소속으로 선택한다. 로컬 초대 인증 후 단체→범위→반대표 역할→담당자를 골라 부여한다. ‘1학년 A반 반대표’처럼 표시된다.
3. ‘학과협의회·학과별 그룹’에서 간부진과 자기 학과 공유 대상을 확인한다. 간부진은 학회장·부학회장이고, 각 학과에는 이들과 반대표가 함께 묶인다. 이 화면은 공유 대상 준비이며 실제 자료실은 아직 없다.
4. 선생님은 학회장 카드의 ‘의장 지정’에서 선출 확인을 입력한다. 의장 자격은 같은 카드에 표시되며 의장만 해제해도 학회장 역할은 유지한다.

실제 학과·학년·반 목록은 학교 확인 후 등록한다. 예시 명칭을 실제 학교 전체 조직도로 간주하지 않는다. [그룹과 권한 모델](design/ACADEMIC_SCOPES.md).

완료 판단은 [조직·권한 프로토타입과 전체 포털의 단계별 완료 기준](PROTOTYPE_COMPLETION.md)을 따른다.
