# 연이음 역할·권한 명세

버전 0.2 / 2026-11-11, Asia/Seoul. S10~S12 사용자 결정과 [조직 구조](ORGANIZATION_MODEL.md)를 기준으로 작성한다. 이 문서는 역할 부여 체계를 명시하며, 문서·예산·회계의 모든 권한이 확정되었다는 뜻은 아니다.

## 1. 사용자 확정사항 (C)

- 첫 버전은 운영 담당자 중심으로 사용한다.
- 학생성공센터 담당 선생님이 서비스 관리자다.
- 담당 선생님이 총학생회 학생회장, 학과협의회 의장, 신문방송국 국장, 연합동아리 연합동아리장 권한을 부여한다.
- 최고 책임자 권한을 받은 사용자는 자기 단체의 하위 부서·직책 역할을 부여할 수 있다.
- 학회장은 부학회장과 반대표 역할을 직접 부여할 수 있다(S11). 부학회장을 거쳐야 반대표를 지정하는 구조로 고정하지 않는다.
- 의장(학과협의회장)은 자기 학과의 학회장을 겸한다. 동일 사용자가 의장 역할과 학회장 역할을 함께 가진다(S12).
- 부장·일반동아리장·부학회장·반대표 등 다른 하위 담당자의 추가 역할 부여는 아직 미정이다.

## 3. 역할 부여 흐름

```text
담당 선생님 (서비스 관리자)
  ├─ 학생회장 권한 부여 ─ 총학생회 하위 담당자 역할 부여
  ├─ 의장 권한 부여 (학회장 겸임)
  │    └─ 학회장 역할 부여 ─ 자기 학과의 부학회장·반대표 역할 부여
  ├─ 국장 권한 부여 ─ 신문방송국 하위 담당자 역할 부여
  └─ 연합동아리장 권한 부여 ─ 연합동아리 하위 담당자 역할 부여

학회장의 부학회장·반대표 역할 부여: 확정
그 밖의 하위 담당자의 추가 역할 부여: 미정
```

최고 책임자의 하위 역할 부여 기능은 확정사항이다. 하위 담당자 1명을 지정할 때마다 선생님의 추가 승인이 필수인 구조로 바꾸지 않는다. 교직원 관리자 역할과 AWS 계정·배포·DB 운영권을 자동으로 연결하지 않는다.

## 5. 적용할 범위 제한 제안 (P)

- 최고 책임자는 자기 단체 하위 역할을 부여한다. 다른 단체 역할·서비스 관리자·자기와 동급인 최고 책임자 역할은 부여할 수 없다.
- 학회장 역할은 특정 학과와 연결한다. 학회장 단독 역할은 자기 학과의 부학회장·반대표만 부여할 수 있게 한다. 요청의 학과 ID가 바뀌어도 다른 학과 역할을 부여할 수 없어야 한다.
- 의장은 같은 계정에서 의장(협의회 범위)과 학회장(자기 학과 범위)을 함께 보유한다. 학회장 겸임이 다른 학회장에게 의장 권한을 자동 부여하지 않는다. 한 역할의 변경·만료·회수를 다른 역할의 자동 회수로 처리하지 않는 기준안을 적용하고 구체 승계는 O-12에서 결정한다.
- 요청에 들어온 단체 ID·학과 ID·역할명·사용자 ID를 서버에서 검증한다. 직책명이나 화면 메뉴를 바꿔 권한을 높일 수 없어야 한다.
- 부여자 자신의 소속·임기가 활성이고 허용된 범위일 때만 부여 요청을 처리한다. 하위 역할의 유효기간은 허용된 운영기 범위를 벗어나지 않게 한다.
- 부여한 사람·대상·조직·담당 범위·역할·시작/종료·회수·사유를 기록한다. 계정이나 임기가 종료되어도 조직 자료와 부여 이력을 삭제하지 않는다.
- 서비스 관리자와 최고 책임자의 기능별 문서·예산 권한은 별도 표로 구체화한다. 관리자 지정만으로 AWS 관리자 키를 제공하는 흐름을 만들지 않는다.
