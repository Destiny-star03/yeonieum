# 연이음 역할·권한 명세

버전 0.6 / 2026-11-12, Asia/Seoul. 기존 S10~S12와 사용자 답변 Q1~54, 이번 DM-C01/02/03/04/05를 반영한다. 개념 관계와 근거는 [도메인 모델](DOMAIN_MODEL.md), 용어는 [용어집](../GLOSSARY.md)을 따른다. C는 확정, P는 구현 제안, O는 미결정이다.

## 1. 사용자 확정사항 (C)

- 담당자 중심으로 사용한다. 담당 선생님이 서비스 관리자이며 각 단체 최고 책임자 권한을 부여한다. 기본 소속은 S18의 5개 단체와 선생님이 추가한 운영 단체다.
- 최고 책임자는 자기 단체 하위 역할을 부여한다. 학회장은 자기 학과의 부학회장·반대표를 직접 지정한다. 부학회장을 거쳐 반대표를 지정하도록 강제하지 않는다.
- 학회장 외 하위 담당자의 재위임은 첫 버전 제외이며 후속 요구가 있을 때 검토한다(Q12).
- 초대자는 자신이 부여할 수 있는 역할·소속 범위만 초대한다. 본인이나 상위 책임자의 권한을 스스로 높이거나 변경하지 못한다(Q6/13).
- 직책 자체로 회계 입력·지출 확인 권한을 자동 부여하지 않는다. 일반 지출은 해당 확인 권한·범위가 있으면 본인 건도 확인할 수 있다(Q11/19/27).
- 반대표는 학과→학년→반 범위다. 같은 반 이름이라도 학과·학년이 다르면 다른 반이다(DM-C01).
- 의장은 같은 계정으로 학과협의회 전체 범위와 자기 학과 학회장 범위를 함께 가진다. 학회장들이 학회장 중 투표로 뽑으며 두 직책의 공식 임기는 같다(DM-C05). 자기 학과 학회장 자격 종료 시 의장도 종료한다(DM-C02).
- 역할별 유효기간·회수를 판정하며 학년도 분류 변경만으로 역할을 종료하지 않는다(Q9/48). 새 책임자는 기존 담당자 목록을 확인하고 필요한 변경을 한다(Q14).
- 소속·직책·임기는 역할 관리 권한자가 바꾸고 이력을 남긴다. 겸임 학생은 한 계정, 교직원은 교직원학번으로 식별한다(Q47/53).

- 최초 의장 선출 전 학회장 계정·역할은 담당 선생님이 등록한다(DM-C06). 이 초기 등록은 의장을 선생님이 선출한다는 뜻이 아니다.

## 2. 역할 부여표

| 부여자 | 대상 역할 | 담당 범위 | 상태 |
|---|---|---|---|
| 담당 선생님 | 학생회장·의장·국장·연합동아리장 | 각각 총학생회·학과협의회·신문방송국·연합동아리 | C |
| 담당 선생님 | 최초 학회장 | 의장 선출 전 학과별 초기 구성 | C: DM-C06 |
| 학생회장 | 부장·차장 등 하위 역할 | 총학생회 내부 | C, 부서 목록·정원은 O |
| 의장 | 학회장·부학회장·반대표 | 학과협의회 내부, 지정한 학과·반 범위 | C |
| 국장 | 부장·차장 등 하위 역할 | 신문방송국 내부 | C, 부서 목록·정원은 O |
| 연합동아리장 | 일반동아리장·운영 담당 하위 역할 | 연합동아리 내부 | C, 실제 참여 담당자는 추가 결정 |
| 학회장 | 부학회장·반대표 | 자기 학과, 반대표는 지정 학년·반 | C |
| 그 밖의 하위 담당자 | 추가 역할 부여 없음 | 첫 버전 제외 | C: Q12 |

위 표는 서비스의 역할 등록·부여 권한이다. 현실의 의장 선출은 학회장들의 투표이며, 선생님은 선출된 의장에게 서비스 역할을 부여한다. 의장이 서비스에서 학회장 역할을 등록한다는 사실을 학회장이나 의장을 현실에서 단독 선출하는 권한으로 해석하지 않는다. 학회장 단독 역할로 타 학과나 의장·학회장·관리자 역할을 부여하지 않는다. 의장 겸임자의 의장 권한은 별도 범위로 평가한다. 하위 담당자 1명 지정 때마다 선생님의 추가 승인을 요구하지 않는다. 교직원 서비스 역할과 개발·배포 운영권은 구분한다.

## 5. 인가·기간의 모델 제안 (P)

- 각 역할 부여 내역에 범위·시작·종료·회수·의존 자격을 명시한다. 의장과 자기 학과 학회장의 공식 임기는 같게 표현하되 선출·서비스 권한 부여 시점과 구분한다. 구현 방식과 DB는 미확정이다.
- 요청 때 대상의 조직·하위 소속·자료 상태·현재 역할을 확인한다. 화면 메뉴나 직책 문자열만으로 허용하지 않는다.
- 의장 자격은 본인 의장 임기와 자기 학과 학회장 자격을 함께 충족해야 한다. 모든 하위 역할이 부여자 퇴임과 동시에 끝나는 것으로 일반화하지 않는다.
- 기간 표현의 경계값은 구현 전 확정한다. 학년도·운영기 필드만으로 역할을 끝내지 않는다.
- 종료·회수 후 조직 자료·회계·감사 이력은 남기고 다음 요청의 권한을 다시 판단한다.

## 6. 남은 결정

초대의 실제 본인 확인 수단, 최초 관리자·부재 대행·계정 복구, 실제 단위 목록·정원·중복 재임, 민감 자료 분류, 초과 예외 처리 결과·후속 절차와 회계 정정 절차를 추가 결정한다. 초과분 최종 확인자는 DM-C03으로 확정됐다. 의장 선출 주체와 공유 임기는 DM-C05로 확정됐고 중도 교체·재선출·최초 학회장 등록은 DM-O04에서 정한다. 이미 확정된 일반 본인 확인·학과/학년/반 구분·의장 종료 의존 관계를 다시 미정으로 취급하지 않는다.

## 관리자 단체·담당자 변경 (S18, 2026-11-13)

- 단체 추가·삭제와 담당자 제거는 서버에서 선생님 권한을 검사한다. 학생의 직접 API 호출도 차단한다.
- 담당자 제거는 정확한 확인 문구 ‘제거하겠습니다’가 필요하다. 관리자·본인 관리자 제거를 차단하며 세션·로그인·현재/예약 역할을 종료하고 과거 기록은 보존한다.
- 단체 삭제는 ‘삭제하겠습니다’ 문구 확인, 운영 제외 및 해당 단체의 역할 회수를 하나의 트랜잭션으로 기록한다. 다른 단체의 역할·계정에는 영향을 주지 않는다.
- 관리자 등록 화면은 운영 단체만 선택한다. 단체 소속만 등록된 계정의 최초 세부 범위는 선생님·해당 단체 최고 책임자가 지정한다. 하위 학회장에게 미배정 전체 단체 담당자의 지정 권한을 확대하지 않는다.
- 단체만 삭제된 계정의 로그인은 유지하지만 그 단체의 업무 역할은 다음 요청부터 유효하지 않다. 일반 학생에게 삭제된 단체의 다른 담당자 목록을 새로 공개하지 않는다. 관리자에게는 삭제·회수 이력을 제공한다.

같은 이름의 삭제 단체를 다시 추가하면 관리자만 기존 단체·하위 소속을 복원할 수 있다. 역할의 revoked_at과 계정 active는 변경하지 않으며 최고 책임자 권한도 다시 부여해야 한다. organization.restored 감사 이력을 남긴다.

## S19 계정 복구·초대·복수 소속 (2026-11-13)

복수 소속은 업무 권한을 자동 확대하지 않는다. 모든 등록 소속에 대한 현재 권한을 검사하고, 다른 단체의 추가 소속·감사 상세를 조회 범위 밖에 공개하지 않는다. 삭제 계정 복구는 학번과 이메일이 모두 일치하는 경우 선생님만 수행한다. 과거 역할·세션·초대 링크는 복구되지 않는다.

초대 수신함과 재발급도 현재 관리 권한을 확인한다. 신규·복구 계정은 로컬 초대 인증 전 로그인과 역할 사용을 차단한다. 실제 메일 발송·실존 확인은 미구현이며 로컬 확인을 실제 본인 확인으로 간주하지 않는다. 기존 데모 계정의 마이그레이션 예외는 운영 인증 근거가 아니다. [세부 구현](design/INVITATIONS.md).

## S20 선생님의 전체 역할 부여·종류 관리

선생님은 최고 책임자·의장·학회장뿐 아니라 부장·차장·부학회장·반대표·동아리 회장/부회장/총무 및 추가 역할을 적합한 범위에 부여할 수 있다. 역할 종류 추가·삭제와 하위 조직 생성은 선생님만 가능하다.

기존 최고 책임자는 자기 단체 하위 역할, 의장은 협의회 전체 범위, 학회장은 자기 학과 범위에서 부여한다. 추가 역할은 이 관리 범위 안에서만 지정하도록 구현했다(P). 추가 역할을 받은 담당자가 새 관리 권한을 갖지는 않는다. 같은 단체의 다른 부서 겸임은 선생님·최고 책임자의 명시적 배정으로 소속을 추가하지만 하위 학회장의 다른 학과 담당자 이동은 금지한다.

종류 삭제는 ‘삭제하겠습니다’ 확인과 서버 관리자 검사를 거쳐 그 단체의 현재·예약 부여를 모두 회수한다. 학회장 삭제의 연결 의장 종료는 유지한다. 종류 복원은 이전 역할을 활성화하지 않는다. 같은 이름의 다른 단체 역할에는 영향을 주지 않는다.

## S22 공유 대상과 위임 구분

학회장·부학회장은 협의회 간부진 자료와 자기 학과 자료의 공유 대상이며, 반대표는 자기 학과 공유 대상이다. 현재 유효한 역할로 판정하며 연락처·학번 등 계정 정보 열람 범위와는 별개다. 공유 명단에는 이름·역할·학과·의장 표시만 제공한다.

학회장의 하위 조직 생성은 자기 학과 학년/반으로 제한하며 신규 학과 생성·타 학과 계정 등록·역할 종류 생성은 허용하지 않는다. 의장은 협의회 학과 하위 학년/반 관리가 가능하고 새 학과 생성은 선생님만 가능하도록 구현했다(P). 부학회장·반대표는 추가 관리 권한을 얻지 않는다. 만료·회수된 역할은 기존 세션에서도 다음 요청부터 생성·공유 참여 권한이 없어야 한다.

의장 지정 버튼은 선생님에게만 제공하며 기존 역할 부여 API에서 동일 인물·학회장 전제·동일 임기·선출 확인을 검사한다. 의장 해제와 학회장 해제를 구분한다. 자료실 구현 시 can_access_sharing_group과 문서 상태·민감도·파일 URL 검사를 함께 적용해야 한다.
